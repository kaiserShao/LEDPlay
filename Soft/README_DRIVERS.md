# 灯带消消乐 —— STM32 驱动说明

> 目标芯片：**STM32F103RCT6**（256KB Flash / 48KB RAM，SYSCLK 72MHz）
> 工程：`LEDAnipop.uvprojx`（Keil MDK，StdPeriph Driver V3.6.0）
> 全部源文件为 **UTF-8** 编码，中断里只做最少的事；业务逻辑跑在 **Keil RTX 的 4 个任务**里，
> 也可以把 `Inc/bsp_config.h` 的 `BSP_USE_RTOS` 改成 0，一键退回"主循环轮询"的裸机版本。

## 3. 各驱动的关键设计

### 3.1 按键（`drv_key`）—— 中断里只做两件事
* EXTI 中断（由 `bsp_exti.c` 统一实现）只做：**记录时间戳 + 置标志位**。
* 消抖（`KEY_DEBOUNCE_MS`）、短按/长按（`KEY_LONG_MS`）判定、事件入队全部在 `drv_key_process()` 中完成，主循环每 1ms 调用一次即可。
* 事件队列：`KEY_EV_DOWN / UP / SHORT / LONG / HOLD`，用 `drv_key_get_event()` 取，或注册 `drv_key_set_callback()` 立即处理。
* 引脚无外部上拉 → `GPIO_Mode_IPU`（内部上拉），按下读取到低电平。

### 3.2 主灯带（`drv_ws2812`，`WS2812_LED_NUM` 颗）—— PWM + DMA 永不间断
* TIM4 输出 PWM，**1 个位 = 1 个 PWM 周期**（周期 = `WS2812_BIT_NS`，WS2812 家族就是 800kHz 档）：
  `0` 码 / `1` 码 = 两个不同的 CCR 值（由 `WS2812_T0H_NS` / `WS2812_T1H_NS` 换算），复位 → CCR=0。
* DMA1_Channel1 **循环模式**把 CCR 值不断写入比较寄存器，全程硬件搬运。
* 缓冲区分三段：前半帧 ｜ 后半帧 ｜ 复位段；每段的元素数由 `WS2812_LED_NUM`、`WS2812_BIT_NS`、
  `WS2812_RESET_US` 算出来（自检的 `WS2812ST cfg` 行会把 `leds/data/buf/bit/T0H/T1H/reset` 全打出来）。
* **半传输中断(HT)** 刷新前半帧、**传输完成中断(TC)** 刷新后半帧+复位段；
  每个中断的余量 = 半帧时间（≈ 半帧位数 × 位周期）→ 灯带数据永不断流。
* 应用层只改颜色缓冲并调用 `ws2812_show()`；中断在帧边界做一次快照，**整帧颜色一致**（不会撕裂）。
* 内存：PWM 缓冲 = 缓冲区位数 × 2 字节 + 颜色缓冲（双缓冲）。
* 亮度在中断里做缩放（`ws2812_set_brightness()`），Mobile 不需要额外内存。
* ⚠ 细节：由于 CCR 使用预装载（必须，否则数据位会出错），上电后的**第一帧会比正常帧多 1 个 0 位**，之后的所有帧都完全正确（复位段会重新对齐）。肉眼不可见。
* 帧间复位按供应商规格书取大于 280µs 的值（宏 `WS2812_RESET_US`；它换算成多少位、帧周期多少 ms，
  自检的 `WS2812ST cfg` 行会打印）：
  规格书表格写"大于 50µs"，但同一份规格书的时序图/数据刷新周期标的是 **≥280µs**，所以取在 280µs 以上
  （当前实际取值见 `WS2812_RESET_US`）。

#### 3.2.0 与供应商规格书（WS2812B）逐项对照

| 参数 | 规格书 | 本固件 | 判定 |
|---|---|---|---|
| VDD | 3.5 ~ 5.3V | 板载 +4.68V | ✓ |
| V_IH | **0.7×VDD**（4.68V → 3.28V；5V → 3.5V） | MCU 3.3V 直连 | ✗ 需电平转换（见 3.2.1 第 3 步第 1 条） |
| V_IL | 0.3×VDD | 0V | ✓ |
| T0H | 0.4µs ±150ns（250~550ns） | `WS2812_T0H_NS` | ✓ |
| T1H | 0.8µs ±150ns（**下限 650ns**） | `WS2812_T1H_NS` | ✓（旧值 600ns 低于下限 ✗，已改） |
| T0L | 0.85µs ±150ns（700~1000ns） | 位周期 − T0H | ✓ |
| T1L | 0.45µs ±150ns（300~600ns） | 位周期 − T1H | ✓（旧值 650ns 超上限 ✗，已改） |
| TH+TL | 1.25µs ±600ns | `WS2812_BIT_NS` | ✓ |
| RES | 表格写 >50µs，时序图/刷新周期写 **≥280µs** | `WS2812_RESET_US` | ✓ |

> "本固件"列只写宏名：**取值一律以 `bsp_config.h` 第 4 节为准**，本文档不抄具体数字；
> 换算出来的 ns / 定时器拍数由自检的 `WS2812ST cfg` 行打印 —— 所以调参数不需要改本文档。

* 三条"**代码没错也永远不亮**"的时序原因，都已按规格书消除：
  1. **T1H 只有 600ns**（< 下限 650ns）→ 1 码高电平太短，灯珠可能采成 0 码。
     现象：发 0xFF（全 1）过去，灯珠收到 0x00 → **一颗都不亮**。→ 现在取在规格书下限以上（`WS2812_T1H_NS`）。
  2. **帧间复位只有 60µs**（低于时序图的 280µs）→ 灯珠可能永远等不到"锁存"，
     上电后一直是灭的。→ 现在取大于 280µs 的 `WS2812_RESET_US`。
  3. 3.3V 直驱 5V 灯带，V_IH 不够（见上表）→ 必须电平转换。

#### 3.2.1 主灯带"从来不亮"排查（先分清"固件没发"还是"硬件没收到"）

**第 0 步（不用改代码、不用示波器）**：连上 ESP32 串口（USART1, 115200）敲 `STATUS`，只看 `frame=`：

| `STATUS` 现象 | 结论 | 下一步 |
|---|---|---|
| `frame=` 稳定均匀地涨（期望值 = 帧率，准确值看自检 `rate B` 行的 `healthy=`） | 固件侧完全正常：DMA 循环 + HT/TC 中断在跑，PB6 上**一定有** 800kHz 数据波形 | 别再改代码，直接查硬件（看下面"硬件 5 条"） |
| `frame=` **一直是 0** | DMA 没被触发 / 中断没进 → PB6 上没有任何数据 → 灯带必然全黑 | 查 `ws2812_is_running()`、`DMA1_Channel1_IRQHandler` 是否被别的模块 `DMA_DeInit` 掉、`ws2812_init()` 是否真的被调用 |
| `frame=` 涨得**很慢 / 乱跳** | 中断被长时间关闭 → 帧率不足（本工程正常只有 DMA / 串口中断，另加按键灯每 20ms 一次、最长 120µs 的最高优先级中断发帧 —— 它不关总中断，但同/低优先级的中断仍会被压住那一会儿） | 典型现象是闪烁/拖尾，而不是全黑 |

顺带确认两个"程序里就能把灯关掉"的开关：`brt=` 不能是 0（`BRT 0` 会把所有颜色乘 0）；`fx=` 不能是 `OFF`（`led_fx_process()` 在 `LED_FX_OFF` 时直接 return，灯就是黑的），正常固件上电是 `COMET`。

**第 1 步：万用表直流档量 PB6（或灯带 DIN 焊盘）对 GND 的平均电压。**
800kHz 是连续数据流，直流档读到的是**占空比平均值**，所以：

| 命令 | PB6 平均电压 | 含义 |
|---|---|---|
| `FILL 0 0 0`（全黑） | ≈ VCC × 0 码占空比（占空比 = `WS2812_T0H_NS` ÷ `WS2812_BIT_NS`） | 有数据在输出 |
| `FILL 255 255 255`（全白） | ≈ VCC × 1 码占空比（占空比 = `WS2812_T1H_NS` ÷ `WS2812_BIT_NS`） | 有数据在输出，且明显比全黑高 = 数据确实在变 |
| 两个都 ≈ **0V** | 这条线没有信号：PB6 虚焊 / 数据线断 / 被短路到 GND | 分别量 MCU 的 PB6 焊盘和灯带的 **DIN** 焊盘，定位断点 |
| 两个都 ≈ **3.3V** | 引脚被拉高，或根本没配成复用输出（`GPIO_Mode_AF_PP`） | 查 `ws2812_init()` 是否被调用、PB6 上是否有外部电路把它顶住 |

（若 PB6 与灯带 DIN 之间加了电平转换/缓冲，把上表读数乘以 `VCC_转换器 / 3.3` 估算；
例如 4.68V 供电的 74LVC1G125：全黑 ≈1.5V、全白 ≈3.0V。）

**第 2 步：上电三步自检**（`Inc/bsp_config.h` → `WS2812_BOOT_SELFTEST = 1U` 后重新编译）。
上电后灯带依次：① 只有第 0 颗红 → ② 整条暗绿 → ③ 整条全白（每步 `WS2812_SELFTEST_MS`），
数码管同步显示 `0001/0002/0003`，ESP32 串口同步打 `WS2812ST …`。串口完整输出应该是：

```
WS2812ST cfg leds=120 data=2880 buf=3120 bit=1250ns T0H=400ns T1H=800ns reset=300us arr=90 ccr0=29 ccr1=58
WS2812ST 1/3 pixel0=red  ONLY first led should light
WS2812ST 2/3 all=dim green  (low current: tests 5V/GND)
WS2812ST 3/3 all=white      (max current: tests power drop)
WS2812ST rate A frame=1234 tim2=5678ms dwt=1
WS2812ST rate B frame=1490 tim2=6678ms frames=256 tim2_dt=1000ms (healthy=256@120led/3120bit)
WS2812ST done: frame=1500 running=1 brt=255 (see README 3.2.1)
```

* `cfg` 行 = **这一版固件实际生效的时序参数**（`bit=` 一位多少 ns、`T0H/T1H` 即 0/1 码高电平），
  末尾 `arr/ccr0/ccr1` = 驱动按实际时钟换算出来的定时器拍数，与同一行的 `bit=/T0H=/T1H=` 必须自洽
  （`arr` × 定时器计数周期 = `bit=`；`ccr0/ccr1` 对 `T0H=/T1H=`）。对不上就说明工程时钟配置
  （SYSCLK/PCLK1）与 `WS2812_BIT_NS` 不匹配。
* `rate A/B` 两行 = 中间夹一次 **1 秒忙等** 的 `frame` / `tim2` 快照，请配合 **PC 串口工具的时间戳** 一起看：
  * PC 上 A/B 两行的真实时间差 = 这个窗口到底有多久；`frames=` = 窗口内 DMA 完成了几帧 → 真实帧率；
  * 真实帧率对上自检 `rate B` 行给出的 `healthy=` → 定时器 / DMA / 中断 / 缓冲位宽在真机上全部确认无误，
    **这时灯带还全黑，就只剩硬件**；
  * `frames` 明显偏小或为 0 → 先查是否有别处长时间关中断，或 DMA 被停掉；
  * 若 PC 上"1 秒"实际走了更久、而 `frames × 帧周期` 正好等于真实耗时 → 帧周期本身是对的，
    只是 `bsp_delay_ms()` 的 DWT 忙等偏慢（纯软件问题，与灯带波形无关）。
* 本自检本身**不依赖任务/效果层**（此时 `app_task_start()` 还没跑、`fx` 还没设置），所以它全黑与 `fx=/brt=` 无关。

| 现象 | 结论 |
|---|---|
| 三步全黑（但串口 `WS2812ST` 行都在打） | 固件在发、灯带没收到 → 硬件：供电 / 共地 / **3.3V 电平** / DIN-DOUT 接反 / 灯珠型号 |
| 只有第 0 颗亮（且随步骤红→绿→白） | MCU → 第 0 颗通了（说明电平勉强够），第 0 颗 → 第 1 颗断了：首颗虚焊/灯带断裂，或波形畸变到第 1 颗就识别不了 |
| ① 只有第 0 颗，②③ 整条都亮 | 灯带链路完全正常 → 问题不在硬件，回到业务/效果层（`fx=` / `brt=` / `rgb=`） |
| ①② 正常，③（全白）才不亮 / 变暗 / 闪 | **供电能力不足**：线太细太长压降大、USB 口电流不够 → 加粗电源线、灯带**双端供电**、就近加 470~1000µF 电解电容 |
| 亮但颜色不对（红↔绿互换、整体错位） | 灯珠颜色顺序是 RGB 而非 GRB（改 `ws2812_encode()` 的字节顺序）；或颗数与 `WS2812_LED_NUM` 不符 |
| 整条随机闪、越靠后越乱 | 时序/复位不匹配：复位已按规格书取值（`WS2812_RESET_US`），仍乱就查 `WS2812_T0H_NS/T1H_NS`、线材压降与共地 |

**第 3 步：硬件上最容易"代码没问题也永远不亮"的 5 条**（按现场出现概率排序）：

1. **用 3.3V 去驱动 5V 灯带**：WS2812 的 V_IH 一般是 **0.7×VDD ≈ 3.5V**，STM32 的 3.3V 输出正好落在临界点，
   最典型现象就是"**一颗都不亮**"（或只有第 0 颗亮）。解决（任选其一）：
   ① 加 **74HCT245 / 74AHCT1G125**（5V 供电的 HCT/AHCT，输入阈值低）做电平转换；
      本板实测方案：**SN74LVC1G125DBVR**（A=PB6、Y→灯带 DIN、OE 接 GND=使能）。
      两个关键条件：**VCC 必须接灯带那一侧的电源（本板 +4.68V），不能接 3.3V**
      （LVC 的 V_OH ≈ VCC-0.1，4.68V 时 ≈4.6V > 0.7×4.68V = 3.28V 才满足灯带的 V_IH；
      输入侧 V_IH 只要 2.0V，3.3V 的 PB6 完全够用）。VCC 就近再并一只 100nF。
      ⚠ **SN74LVC1G126 与 1G125 脚位完全一样，但 OE 是高有效**：若错用 126 且把 OE 接 GND，
      输出进高阻 → 灯带全黑，务必核对型号/丝印；
   ② 灯带 VCC 串一只 1N4148 降到 ~4.3V（仍在灯珠工作范围内）；
   ③ 数据线缩短到 10cm 以内（走线电容小，3.3V 也可能被识别，但不保证）。
2. **灯带没供电 / 没共地**：量灯带 VCC ≈ 5V；**MCU 的 GND 必须和灯带的 GND 直接连在一起**
   （各自通过 USB 接地是错的：数据线没有共同参考电平 → 全黑）。
3. **DIN/DOUT 接反**：数据从 MCU 进 **DIN**，灯带上有箭头，只能顺着箭头方向传；接在 DOUT 或灯带末端上永远不亮。
4. **灯珠型号不是普通 WS2812B**：SK6812 **RGBW** 是 32 位/颗（本驱动按 24 位发 → 整体错位）；
   12V 灯带（WS2815 等）不是 800kHz 单线时序；APA102/SK9822 是 CLK+DATA 双线 SPI → **本驱动完全不适用**。
5. **PB6 到灯带之间还有一级反相/缓冲电路**：有些板子为了驱动能力加了三极管/缓冲器，可能把数据**反相** → 全黑。
   直接量灯带 **DIN** 焊盘：正确波形是"位周期 = `WS2812_BIT_NS`、高电平 = `WS2812_T0H_NS`（0 码）/
   `WS2812_T1H_NS`（1 码）的向上正脉冲"，不是它的反相。

**第 4 步：分清"固件没发"还是"硬件没收到"。**
按键灯是**独立**的一条通路（PC4 + 软件时序，见 3.3），所以"按键灯能亮"只说明 PC4 这条线和那条灯带没问题，
**说明不了主灯带本体**；反过来按键灯不亮也不代表主灯带坏了 —— 别拿它当主灯带的对照：
* `STATUS` 的 `frame=` 在涨 + PB6 平均电压随 `FILL` 变化 → 固件侧没问题，直接查灯带本体 / 接线；
* PB6 波形正常但灯带不亮 → 量灯带 **DIN** 焊盘（PB6 与 DIN 之间断线 / 虚焊最常见）。

> 说明：本驱动是"CCR 预装载 + DMA 在比较匹配时写 CCR"的经典方案，上电**第一帧会多 1 个 0 位**，
> 之后所有帧完全正确（见 3.2 节末尾），这不会导致全黑，排查时可以忽略。

### 3.3 按键灯（`drv_keyled`）—— PC4 独立数据线，位时序抄主灯带

> **硬件形态**：按键灯带（`KEYLED_NUM` 颗 WS2812）的 DIN 接 **PC4**，是一条**独立**的数据线
> （与主灯带的 PB6 分开）。
> **位时序**：不再单独调一套，直接沿用主灯带那一套（第 4 节 `WS2812_*`）—— 主灯带时序已经实测好用，
> 两条支路用同样的时间，同型号灯珠才会给同样的判定：
>
> | 码 | 高电平 | 低电平 | 合计 |
> |---|---|---|---|
> | `0` 码 | `KEYLED_T0H_NS`（= `WS2812_T0H_NS`） | `KEYLED_T0L_NS`（= `WS2812_BIT_NS − WS2812_T0H_NS`） | `WS2812_BIT_NS` |
> | `1` 码 | `KEYLED_T1H_NS`（= `WS2812_T1H_NS`） | `KEYLED_T1L_NS`（= `WS2812_BIT_NS − WS2812_T1H_NS`） | `WS2812_BIT_NS` |
>
> 帧间复位 `KEYLED_RESET_US` = `WS2812_RESET_US`。也就是说按键灯看到的波形与主灯带**逐位相同**；
> 改主灯带时序（第 4 节）时，第 5 节的 `KEYLED_*` 会跟着一起变（它们就是引用 `WS2812_*` 算出来的）。

* 驱动**不占用任何定时器通道**（PC4 在 STM32F103 上没有定时器复用功能，只能软件翻转管脚）：
  时间基准交给一个空闲的**基本定时器** `KEYLED_TIM = TIM6`（只有计数器 + 更新中断：不占引脚 /
  比较通道 / DMA）。需要发帧时先在任务里「请求」，96 位时序由它的更新中断一次发完（约 120µs），
  每段长度 = 数 `KEYLED_TIM->CNT` 的拍数（72MHz，1 拍 = 13.89ns）—— 段长就是 `KEYLED_T?H_NS` 配置值
  本身，**不需要上电自标定**，也不依赖 DWT。发帧期间靠中断优先级 `BSP_IRQ_PRIO_KEYLED_TIM`(0)
  保证不被打断，所以**不用关总中断**（回退成老办法：`bsp_config.h` 第 5 节 `KEYLED_USE_TIM_IRQ = 0`，
  DWT 忙等 + 自标定 + 关中断，其它代码不用改）。
* 效果仍是 `KEYLED_FX_OFF / STATIC / BLINK / BREATHE`，亮度用 `keyled_set_brightness()`（默认满亮）；
  `keyled_process()` 内部按 `KEYLED_REFRESH_MS` 限速（在灯效任务里调用，见 3.9 节），并且只在颜色
  真的变了才发一帧。`keyled_set_*` 可以来自任何任务，驱动内部用一把 `bsp_mutex_t` 保护整组颜色。
* **现场试色 / 调时序**（命令见第 4 节）：
  * `KEYLED 0 255 0 0`（第 1 颗红）、`KEYLED 0 0 0 255`（第 1 颗蓝）、`KEYLED ALL 0 255 0`（四颗绿）、
    `KEYLED ALL 0 0 0`（全灭）；
  * `KEYLED T0H|T0L|T1H|T1L <ns>`：实时改四段电平（传 `0` = 用回配置默认值），改完立即重发一帧，不用重编；
  * `KEYLED INVERT <0|1>`：数据线上串了反相器 / 三极管时用；
  * `KEYLED INIT [n]`：连发 `n` 帧全灭（默认 `KEYLED_INIT_FRAMES` 帧）—— 灯珠被噪声 /
    上一个项目锁存成白色时，先用它压回全灭，再发颜色命令；
  * `KEYLED DIAG`：打印四段时序（目标 ns / 实际计数拍数 / 扣掉的固定开销）、`meas`（最近一帧
    「实测 − 目标」，单位拍：定时器方式下就是忙等循环的收尾误差，填进 `KEYLED_TIM_WAIT_COMP_CYC`
    就把段长抠准了）、`tim=`（1 = 定时器中断发帧）`frames=`（中断真正发出去的帧数：发一条颜色
    命令后它应该变大，这是「中断发帧这条路活着」的最直接证据）、`invert=` `calib=` `fclk=`，
    线路自检 `line low/high`（驱动低 / 高时引脚读回，应分别是 `0`/`1`）以及每路 `set=`（设定色）/ `out=`。
* **发帧时机**：`keyled_process()` 由灯效任务每 10ms 调一次。发帧那 120µs 是「最高优先级中断里
  数拍翻转 PC4」，所以**只有**在 `ESP32_RX_USE_DMA = 0`（串口靠 USART1 中断逐字节搬）时，
  串口正在收一条命令（`esp32_line_pending()` 或接收缓冲非空）才**跳过这一拍**，免得把正在接收的
  字节挤掉（现象 = 命令少字母 / 回一串乱码，见 3.5 节）。默认的 DMA 收数方式下字节由硬件搬走，
  谁也不影响，不用跳。
* **发白 / 串色 / 不亮怎么查**：
  * 发白、颜色乱 → 灯珠把 `0` 码读成了 `1` 码（高电平偏长）或整帧错位：先 `KEYLED DIAG` 看四段实测，
    再按 `KEYLED T0H 250` / `KEYLED T1H 700` / `KEYLED T0L 750` 之类逐项试（不用重编），
    认准的组合写回 `bsp_config.h` 第 5 节；
  * 整条不亮 → 量 PC4 → 灯带 DIN、共地、灯带供电；PC4 直驱 3.3V 对 5V 灯带同样有 V_IH 风险，
    必要时加电平转换（见 3.2.1 第 3 步第 1 条）；
  * 只有第 1 颗亮 → 首颗之后的灯带断线 / 虚焊。
* 按键灯与主灯带 / 游戏层**互不重叠**：它是另一条数据线，游戏层照样用整条主灯带
  （`WSGAME_MAX_LEDS = WS2812_LED_NUM`，见 3.10 节）。

### 3.4 数码管（`drv_hc595`）
* 段码位：bit0~bit6 = a~g，bit7 = dp；`HC595_ACTIVE_LEVEL` 选择共阴/共阳（共阳自动取反）。
* `hc595_show_int(1234)`、`hc595_show_digits("A1-2")`、`hc595_set_dp_mask()`、`hc595_clear()`。
* 位序与焊接顺序不一致时用 `HC595_DIGIT_REVERSE` 切换（`bsp_config.h` 第 6 节）：
  **本板实测是反的**（第 1 位会显示到第 4 位上），所以默认 `HC595_DIGIT_REVERSE = 1`
  （即 `hc595_digit_map[] = {3,2,1,0}`）；换板子若发现又反了，改回 `0U` 即可。

#### 74HC595 级联接线速查（DIP16）

| 595 引脚 | 名称 | 接到哪里 |
|---|---|---|
| **14** | DS / SER | MCU 的 SDI（本工程 **PC6**）——**数据入口，接错这里就永远不显示** |
| 11 | SHCP / SRCLK | MCU 的 SCLK（**PC7**），上升沿把数据移入 |
| 12 | STCP / RCLK | MCU 的 LOAD（**PC8**），上升沿把移位寄存器送到输出锁存器 |
| 13 | OE̅ | **必须接 GND**（悬空/接高 → 输出高阻 → 全黑） |
| 10 | MR̅ | **必须接 VCC**（拉低 → 移位寄存器清零 → 一直不亮） |
| 9 | QH′ | 级联到**下一片的 14 脚**（这是输出，不是给 MCU 用的输入！） |
| 16 / 8 | VCC / GND | 5V / GND，每片旁边 0.1µF 去耦 |

> 本项目的实际故障就出在这里：PC6 接到了 595 的 **9 脚（QH′，级联输出）** 而不是 **14 脚（DS，数据入口）**，
> 数据永远进不了移位寄存器，输出锁存器一直停留在上电的全 0 → 共阳屏表现为**全段 + 小数点常亮**（见下表）。

#### 上电 3 步自检（`HC595_BOOT_SELFTEST`，默认 **0** = 关闭）

需要排查数码管时把它置 **1** 重新编译：上电后数码管按顺序走 `8888` → 全灭 → `1234`
（每步显示 `HC595_SELFTEST_MS`），按下面这张表对号入座，一次就能定位问题；
排完改回 0（正常固件不需要这几百毫秒的延时）。

| 现象 | 原因 | 处理 |
|---|---|---|
| **全部段连小数点一起常亮** | 板子是**共阳**，但 `HC595_ACTIVE_LEVEL` 写成了 `1U`（共阴）：清屏/空格的段码是 `0x00`，不取反直接输出 → 595 八个输出全低 → 共阳管全部点亮 | 把 `HC595_ACTIVE_LEVEL` 改成 **`0U`**（本工程默认已是 `0U`） |
| 改好极性后**依然全亮、任何时刻都不变** | 数据根本没移位进 595：PC6 接到了 9 脚（QH′）而不是 14 脚（DS），或 595 的 `OE` 被拉高、`MR` 被拉低、`VCC/GND` 没接好 | 按上面的接线速查表逐脚核对；再用示波器/逻辑笔量 PC6/PC7/PC8 有没有跳变 |
| 显示**满是"Ｌ"或 g 段**（每一步都只有 g+小数点亮） | 段码送反 + 位序对不上（典型是共阴表配共阳屏的中间态） | 先确认共阴/共阳，再调 `hc595_digit_map[]` |
| `8888` 正常，`1234` 显示的**数字顺序左右颠倒** | 级联方向与预期相反（先移入的字节落在最近的 595 上） | 把 `hc595_digit_map[]` 改成 `{3U, 2U, 1U, 0U}` |
| `8888` 时**小数点也亮** | 段码表里 `dp` 不是 bit7，或硬件 dp 接在别的 Q 上 | 对照原理图改 `hc595_char_to_seg()` 里的 bit7 与硬件 Q 的对应关系 |
| 某一段**永远不亮**（例如 a 段） | 该段 LED / 限流电阻 / 595 对应输出脚虚焊 | 硬件检查，与软件无关 |

> 74HC595 上电时输出寄存器是 **全 0**，所以共阳屏在"程序还没写数据"或"数据没送进去"时，
> 表现都是**全亮**——这就是上电瞬间看到全亮（含小数点）的原因。

### 3.5 ESP32-C3 串口（`drv_esp32`）
* **接收 = DMA 环形搬运**（`ESP32_RX_USE_DMA = 1`，默认）：USART1_RX 由 **DMA1_Channel5** 循环写进
  `s_dma_buf[]`，`esp32_process()` 再把字节搬进 512B 环形缓冲、按行拆包 → 回调 `esp32_set_rx_handler()`。
  > **为什么必须这样**：STM32F103 的 USART 接收寄存器只有 **1 个字节**。原来用"每字节一次 RXNE 中断"时，
  > 只要有 87µs（115200 下一个字节的时间）进不去中断，这个字节就**永久丢失**。而本工程正好有两个
  > "长时间不给串口进中断"的家伙：① 主灯带 DMA 中断里的 `ws2812_encode()`（编 60 颗灯 = 1000+ 次循环，
  > 每 1.8ms 来一次）；② 按键灯发帧时的约 120µs（现在是优先级 0 的中断在数拍翻转 PC4，同/低优先级
  > 的中断都挤不进去；老办法是直接 `__disable_irq()`，每 20ms 一次）。
  > 交给 DMA 后，字节是**硬件**直接写进 RAM 的：CPU 关不关中断、被哪个中断抢占都照收 ——
  > 这类"命令老是少字母"的问题从根上消失（同时 CPU 也少了几千次中断）。
  > 代价是收数不再有中断唤醒，所以 `esp32_process()` **必须被周期性调用**
  > （通信任务每轮 + 裸机主循环每圈都调）；`APP_TASK_COMM_PERIOD_MS`(10ms) 就是命令的最大响应延迟，
  > `ESP32_RX_DMA_SIZE`(512B) 则是"两次调用之间最多能积压多少字节"（≈44ms 满速流量）。
  > 实在不能用 DMA 时把它设成 `0` 就退回老的中断方式（其它代码不用改）。
* **中断优先级顺序不能反**：`BSP_IRQ_PRIO_ESP32_UART`(0) 必须**比** `BSP_IRQ_PRIO_WS2812_DMA`(1) **高**
  （数值越小越高）。主灯带被串口中断（3µs 级）打断毫无影响——它手上还有 1.8ms 余量；反过来就会丢命令字母。
  改完主灯带若出现闪烁/拖尾，先看 `STATUS` 里的 `frame=` 是否还在稳定增长。
* **按键灯发帧中断给 0**（`BSP_IRQ_PRIO_KEYLED_TIM`）：一帧 120µs 全程在 TIM6 更新中断里翻转 PC4，
  段长直接数 `CNT` 拍数。给最高优先级是为了"不被打断"—— 所以整个发帧过程**不关总中断**。
  代价是**同优先级**的中断（`BSP_IRQ_PRIO_ESP32_UART` = 0）在这 120µs 里也得等着，
  因此 `ESP32_RX_USE_DMA = 0` 时才需要下面那条"按键灯闸门"。
* 发送：`esp32_send/send_str/send_line/printf`（整串一次发完 + 互斥锁 + TXE/TC 超时保护，不会死等、不会互相插队）。
* 统计接口：`esp32_rx_total/rx_lines/rx_overflows/rx_errors/rx_dropped/rx_long_lines()`。
* **收命令的规矩**（照着"命令少字母 / 回一串乱码"这类现象加固的）：
  1. **只收可打印 ASCII**：`0x00~0x1F`、`0x7F`、`>= 0x80` 的字节直接丢掉（计入 `drop`）——
     这些通常是线路噪声或桥接芯片自己的日志，混进命令只会拼成乱码；`Tab` 当空格。
  2. **超长整行作废**：超过 `ESP32_LINE_MAX`(127) 之后**丢弃到下一个换行**（计入 `long`），
     不再"清空计数接着存"。旧版接着存会把一串没有换行的数据拼成一条命令，
     应答就是 `ERR UNKNOWN XXXYYYZZZ`（几段残缺命令粘在一起）。
  3. **静默收尾**：最后一个字节之后静默 `ESP32_LINE_IDLE_MS`(100ms) 还没等到换行，就把这一段
     当整行处理。有些上位机/工具发完命令**不带 `\r\n`**，没有这条规则就是"发什么都没反应"。
     （把它设成 `0` = 关掉这条规则，只认 `\r\n`；人工逐字符慢敲、间隔超过这个值时请关掉。）
  4. `esp32_process()` 负责搬运 + 拆行 + 收尾判定，所以它每 10ms 都要被调一次（见上面 DMA 那段）。
* **按键灯闸门**（第二道保险，**只在 `ESP32_RX_USE_DMA = 0` 时编译进来**）：按键灯发一帧要占用 CPU
  约 120µs（最高优先级中断里数拍翻转 PC4）。所以在"逐字节 RXNE 中断"的收数方式下，灯光任务在
  `esp32_line_pending()` 或 `esp32_rx_available()` 非 0（正在收命令 / 缓冲里还有没取走的字节）时
  **先不发按键灯**，等这行收完再发（颜色晚几十毫秒，看不出来）；用 DMA 收数时字节由硬件搬走，
  这条闸门被 `#if (ESP32_RX_USE_DMA == 0U)` 整段编译掉，颜色不会白等。
* **原始接收缓冲（全局，专治"到底收到了什么"）**：
  * `g_esp32_rx_cap[]`：收到的**每一个字节**（过滤之前）按到达顺序存一份；
    `g_esp32_rx_flg[]`：同下标存这个字节的标记（`ESP32_CAP_FLAG_ERR/EOL/GAP/FILTER/BUFOVF/DMAOVF`）；
    `g_esp32_rx_cap_idx` = 下一个写入位置（最新一个字节在 `idx-1`），`g_esp32_rx_cap_total` = 累计字节数。
  * 环形保存最近 `ESP32_CAP_SIZE`(1024) 个字节，满了就覆盖最老的（不会占着 RAM 无限增长）。
  * 标记含义：`E` = 这个字节到达时 USART 报了错（ORE/FE/NE/PE，多半就是丢了上一个字节）、
    `L` = 换行、`G` = 与上一个字节静默超过 `ESP32_CAP_GAP_MS`（上位机换命令了）、
    `F` = 被行过滤器丢掉、`O` = 环形缓冲满没存下、`D` = DMA 窗口被覆盖（这里少了若干个字节）。
  * 三种看法：① Keil 里 Watch `g_esp32_rx_cap` / `g_esp32_rx_flg` / `g_esp32_rx_cap_idx`；
    ② 串口 `UART DUMP [n|ALL]`（十六进制 + ASCII + FLG 标记行，最直观）；
    ③ 串口 `UART RAW 1` 边收边打。
* **链路自检命令**：`UART` 打印计数器 + `last=`（最近真正解析过的整行）；判读见第 4 节表格与第 7 节排查表。
  > 判读口诀：`UART DUMP` 的字节和上位机发出去的**逐字节对**——
  > **少字节** → 看那个位置的标记（`E`/`D`/`O`）；**多字节** → 桥接芯片把自己的日志混进来了；
  > **一个都不少但命令还是错** → 不是"收"的问题（查拆行/参数/逻辑）。

> **别漏了 ESP32-C3 那一侧的桥接固件**：`INO\ESP32C3\ESP32C3.ino`。
> 旧版是"一圈 `loop()` 只搬 1 个字节"，电脑发一整行 / STM32 回一整行时，只要中间有一处缓冲
> 没被及时取走就会丢/挤字节；现已改成**一次搬一整批（≤256B）**，并把两侧接收缓冲调到 1024B。
> 改完必须重新上传到 ESP32-C3（板子选 ESP32C3 Dev Module，端口选 USB 那个串口；
> 旧版留档 `Soft/Doc/orig_esp32c3_bridge.ino.bak`）。电脑端工具的波特率随意（USB 侧与波特率无关），
> STM32 侧固定 115200 8N1。
>
> **回环测试能证明什么、不能证明什么**：在 ESP32-C3 上把 GPIO0(TX)/GPIO1(RX) 短接做回环，
> 只能证明**桥接芯片这一侧**（USB CDC ↔ UART1）通；它**不覆盖**"ESP32 的 TX → STM32 的 PA10"
> 这一段（接线、共地、电平、STM32 到底有没有收到）。所以要配合 STM32 侧的 `UART` /
> `UART DUMP` 看**STM32 实际收到了什么字节**，两边一对比就知道丢在哪一段了。


### 3.6 语音模块 WT2003HX（`drv_wt2003h`）—— 只保留实测可用的几条命令

接线：`USART3`，`PB10 = TX` / `PB11 = RX`，9600 8N1（本板不使用模块的 Key 口）。
业务层只需要记一个入口：

```c
wt2003_play_name(WT2003_FILE_KEY);   /* 播 U 盘根目录里的 0001.mp3（按键音） */
```

| 命令 | 帧（实测可用） | 驱动接口 |
|---|---|---|
| 设置音量 | `7E 04 AE <vol> <ck> EF` | `wt2003_set_volume(v)` |
| 查询文件总数 | `7E 03 C4 C7 EF` | `wt2003_query_count()` / `wt2003_get_count()` |
| 按根目录索引播放 | `7E 05 9D <高> <低> <ck> EF` | `wt2003_play_index(n)` |
| 按文件名播放 | `7E 07 9E <4 字符> <ck> EF` | `wt2003_play_name("0001")` |
| 指定播放模式 | `7E 04 AF <mode> <ck> EF` | `wt2003_set_mode(m)` |
| 停止播放 | `7E 03 AA AD EF` | `wt2003_stop()` |
| **插播（叠加）** | `7E 06 B1 <标示字> <高> <低> <ck> EF` | `wt2003_insert_index(n)` |

> 插播的**标示字**（`B1` 数据第 1 字节，手册 4.1.2.14）：`00` = **FLASH（外挂 SPI Flash 片）** / `02` = **U 盘**；
> 例 外挂 Flash 曲目 3 → `7E 06 B1 00 00 03 BA EF`。插播**叠在**正在播的背景音上，背景音不停、也不重头。

* 帧格式：`7E | 长度 | 命令 | 数据… | 校验码 | EF`；
  长度 = `自身(1) + 命令(1) + N(数据) + 校验码(1)`，校验码 = 从"长度"字节起逐字节累加和（mod 256）。
  例：索引 1 → `7E 05 9D 00 01 A3 EF`；`"0001"` → `7E 07 9E 30 30 30 31 66 EF`。
* **两条命令之间至少隔 `WT2003_CMD_GAP_MS`（默认 30ms）**，发太密模块会丢命令（驱动已自动保证）。
* 音频文件放 **U 盘根目录**，文件名固定 **4 个字符**（`0001.mp3`…，扩展名另算）；
  文件名宏在 `bsp_config.h` 第 8.1 节：`WT2003_FILE_KEY`(按键音) / `_CLEAR`(消除音效，消消乐命中也用它) /
  `_START` / `_OVER` / `_POWER_OFF` / `WT2003_BOOT_FILE`(开机音) /
  `WT2003_FILE_BGM`(消消乐背景音 `0007`) / `_SHOT`(发射 `0008`) / `_MISS`(未消除 `0009`)。
* 上电顺序：等 `WT2003_BOOT_DELAY_MS`（300ms，模块上电要做内部初始化，命令发太早会被忽略）
  →（可选）设音量 →（可选）查文件总数 →（可选）播开机音；三个开关都在 `bsp_config.h` 第 8 节
  （`WT2003_SET_VOLUME_ON_BOOT` / `WT2003_QUERY_COUNT_ON_BOOT` / `WT2003_BOOT_PLAY`）。
* 排查（`WT2003_TRACE = 1`，默认开）：收发帧直接从 ESP32 串口打出来 ——
  `WTTX 7E 05 9D 00 01 A3 EF`（真正发出去的帧）、`WTRX 9D 00`（模块回帧）、
  `WTRXCOUNT 6`（0xC4 查到的文件总数；`0` = 模块在盘上看不到文件）。
* 面板命令见第 4 节：`VOICE 0001` / `VPLAY 1` / `VINS 1`(`VINS 1 2` 换介质) / `VSCAN` / `VMODE 1` / `VOL 20` / `VNUM`。
* **想试手册里其它命令码？** 用第 4 节的 `VRAW <hex…>` **原样发**（免烧录、免改代码）：
  `VRAW 7E03C4C7EF`（查文件总数）、`VRAW 7E 06 B1 00 00 08 BF EF`（`B1` 插播 8 号）。
  校验码自己算：**长度 = 1(自身) + 1(命令) + N(数据) + 1(校验)**、
  **校验码 = 从"长度"字节起逐字节累加和 mod 256**（`7E 06 B1 00 00 08` → 长度 `06`，
  校验 `06+B1+00+00+08 = 0xBF`）；发完看 `WTTX` 行确认、听喇叭确认。
  也可以**完全不经过 STM32**：USB-TTL（3.3V）直接接模块的 RX/TX/GND，**9600 8N1**、
  串口助手切十六进制发同样的字节 —— 记得先断开模块 RX 上的 PB10（别和 MCU 抢着发）并共地。
* **只听到开机/关机音（`0005`/`0006`），背景音和音效都不响？** 先分清是"命令不对"还是"文件不在"——
  开机音/关机音走的是**和背景音同一条 `9E` 命令**（`main.c` 里 `wt2003_play_name(WT2003_BOOT_FILE)`），
  所以 `9E` 这条路本身是通的，问题多半在**文件本身**。按顺序查：
  1. `VNUM` → 看串口 `WTRXCOUNT n`：**`n` 小于你的最大编号就是文件没拷进去**（例如只有 6 个 → `0007/0008/0009` 不在盘里）；
     文件名必须是**根目录 + 正好 4 个字符**（`0007.mp3`），放子目录/名字 3 位或 5 位都不认。
  2. `VNAME 0007`（或 `VOICE 0007`）单独点播：响 = 文件在，问题在背景音那套 `AF 01`+点播的配合
     （`VMODE 1` 再 `VNAME 0007` 对照一下就知道是不是 `AF` 的锅）；不响 = 文件/格式问题
     （有的模块只吃 MP3 44.1kHz 128kbps，WAV 要 PCM 16bit）。
  3. 音效放在 **WT2003H 外挂的 SPI Flash** 上，用**插播**（`0xB1`，标示字 `00` = FLASH）取：
     `VINS 1` / `VINS 2` / `VINS 3`（`VSCAN 1 3` 一次扫完，用耳朵对号）。
     ⚠ **标示字/介质对不上就看不出效果**：`B1` 的标示字 `00` = **FLASH（外挂 SPI Flash）**、
     `02` = **U 盘**（手册 4.1.2.14）—— 写成 `02` 而 U 盘上没这三个文件，自然没声；
     早期"这块模块不吃插播"的结论就是没把标示字和介质对上造成的。
     `255` = 不带标示字的 2 字节形式（备用，本工程不用）。
  4. `VNAME 0008` / `VNAME 0009` / `VNAME 0002`（空闲时）逐个听：**这几个文件本身有没有声**。
     有 = 文件没问题，按第 3 步改音效发法；没有 = 文件/格式问题（重转 MP3 44.1kHz/128kbps、
     名字正好 4 个字符、放盘根目录），换命令也救不回来。
  5. 游戏里"一局到底一声都不响"再查两处**代码侧开关**：① `main.c` 的 `wsgame_init()` **必须被调用**
     （注释掉它 = 游戏不开局，`bgm_start()` / `sfx_play()` 一帧都发不出去）；
     ② `WSGAME_BGM_DELAY_MS`（默认 `4000`）让背景音等开机提示音 `0006` 播完再点 ——
     模块"正在播放"时收到的命令可能被丢掉，起太早背景音一次也起不来。
* 其余命令（`A0/A6/A7/C0..CB/B6/D2`…）、Key 口（K1~K3）、上电自检、按文件名轮播
  **全部退役**，
  退役代码 + 旧命令表 + 历年排查日志留档在
  `Doc/WT2003_退役命令与自检备份.md`（精简前的完整源码在 `Doc/orig_20261005/`）。
  * 例外：**"把任意字节原样发出去"这条能力回来了**，就是第 4 节的 `VRAW`（驱动 `wt2003_send_raw()`，
    复刻退役的 `WTRAW`，行文/用法一致）—— 需要临时试手册里任意一帧时用它，不用再改代码重烧。

### 3.7 一键开关机（`drv_power`）
* `power_init()`：**先开 GPIOC 时钟 → 立即把 PC3 拉成"保持供电"电平 → 再配置为推挽输出**（顺序很关键，否则松手断电）。
* PA7 电源键：内部上拉 + EXTI7 下降沿（中断只记时间戳），主循环按 `POWER_KEY_POLL_MS` 轮询消抖：
  * 长按到 `POWER_OFF_LONG_MS` → `power_request_shutdown()`：先调用关机回调（播提示音/关灯/存参数），
    延时 `POWER_SHUTDOWN_NOTICE_MS` 后拉掉 PC3 断电；
  * 长按到 `POWER_FORCE_OFF_MS` → 立即断电（强力兜底）；
  * 短按 → 短按回调（业务层自定义，例：上报 WiFi）。
* 调试时 USB 供电不会真的掉电，程序会停在 `__WFI()` 死循环里（`POWER_HARD_CUT_LOOP=1`）；不想这样就把该宏改成 0。

### 3.8 时间基准（`bsp_time`）
* 延时：DWT->CYCCNT 周期计数，72MHz 下 13.9ns 分辨率（WS2812 软件时序靠它）。
* 时间戳：TIM2 是 16 位，因此配置成 **1ms 中断**（PSC=71、ARR=999），中断里累加软件计数器：
  * `bsp_time_ms()` 32 位毫秒（49.7 天回绕）
  * `bsp_time_us()` 微秒（读"毫秒累加值 + 当前 1µs 计数"，带重读保护）
* 判断时间差一律用 `bsp_elapsed_ms()/bsp_elapsed_us()`（无符号差值，跨回绕安全）。
* 若你的板子不方便用 TIM2，可以把 `bsp_time.c` 里的 `BSP_TIME_TIM` 换成 TIM3/TIM5（注意别和灯带的 TIM4 冲突）。

### 3.9 RTOS 任务划分与资源保护（`app_task` + `bsp_rtos`）

> 只想跑裸机？把 `Inc/bsp_config.h` 里的 `BSP_USE_RTOS` 改成 0 即可：`app_task_start()`
> 会立刻返回，由 `main.c` 末尾的主循环轮询所有 `*_process()`，功能完全一样（便于对比/移植）。

四个任务（周期、优先级都在 `bsp_config.h` 第 9 节）：

| 任务 | 周期 | 优先级 | 干什么 |
|---|---|---|---|
| `input` | 5ms | AboveNormal | `drv_key_process()` 消抖 + 短按/长按、`power_process()` 电源键 |
| `light` | 10ms | Normal | `led_fx_process()` 灯带动画、`keyled_process()` 按键灯（**仅 `ESP32_RX_USE_DMA = 0` 且串口正在收命令时先不发**，见 3.5） |
| `comm` | 100ms（有数据/换行立刻唤醒） | Normal | `esp32_wait_data()` → `esp32_process()` → `app_cmd_process()`（**每轮都调 `esp32_process()`**，它负责"静默收尾"） |
| `voice` | 10ms | BelowNormal | `wt2003_process()`（解析语音模块回帧；发命令由业务层直接调驱动） |

三条"不会被 RTOS 破坏"的设计原则：

1. **精确时序不交给任务**：WS2812 的 PWM+DMA、按键灯位打（一帧 120µs 在 TIM6 中断里数拍翻转 PC4，不关中断）、74HC595 移位、
   `bsp_delay_us()` 仍然在中断里或短临界区里完成，任务只负责算颜色、填缓冲。
2. **时间判断仍然用 TIM2**：`bsp_time_ms()` / `bsp_elapsed_ms()` 来自 TIM2 中断，与 RTX 的
   SysTick 相互独立，跨任务跨中断都安全；所以任务周期抖动不影响按键/动画的正确性。
   `bsp_sleep_ms()` 只是"让出 CPU"，不要把它当成精确延时。
3. **共享资源一把锁**：串口发送（`drv_esp32`）、灯带颜色缓冲（`drv_ws2812`，配合
   `ws2812_lock()/ws2812_unlock()` 包住"改多颗 + show"）、按键灯缓冲（`drv_keyled`）各自用
   `bsp_mutex_t` 保护；"中断 → 任务"的通知用 `bsp_signal_t`（`esp32_wait_data()`、
   `drv_key_wait_event()`）等，不再用全局标志忙等。

必须在 `RTE\CMSIS\RTX_Conf_CM.c` 里核对的三项：

* `OS_CLOCK` = **72000000**（必须等于 `BSP_SYSCLK_HZ`，否则 `osDelay` 的超时会成比例偏差）；
* `OS_STKSIZE` = 256（单位: 字, 即 1KB/任务）、`OS_MAINSTKSIZE` = 256；
* `OS_TASKCNT` = 8（本工程用 4 个用户任务 + 定时器任务，留有余量）。

### 3.10 灯带消消乐（`app_wsgame`）—— 游戏层

> 玩法：灯带是一条**运输带**。随机 **蓝 / 绿 / 紫** 的单颗灯从**远端**冒出来，整条缓慢往
> **近端**挪；每 `WSGAME_SPAWN_MS` 在远端再补一颗 —— 前一颗没消掉，后面就紧跟着再来一颗，
> 场上的灯越积越多，一起往近端挤。
> 近端按 **Key1/Key2/Key3** = 朝远端**发射**一颗同色子弹（比灯快得多）；
> 子弹撞上**同色**灯 → 两颗一起消失（白闪 + 得分）；
> 撞上**不同色** → 子弹**自己也消失**（色块留在原地、不得分，也不会挡住后面的子弹）；
> 一直没被消掉的灯走到近端 = **漏掉**（只计数不扣分，近端灰白微亮一下提示），然后消失。

**远 / 近端与方向**

| 名称 | 逻辑索引 | 物理灯珠 | 说明 |
|---|---|---|---|
| 近端 | 0 | 0 | 数据入口（DIN）这一端：按键在这头，灯冲着你来，**子弹从这里发出** |
| 远端 | `WSGAME_MAX_LEDS`−1 | `WS2812_LED_NUM`−1 | 灯带末端：**灯从这里冒出来**，子弹飞到这儿就收回 |

* 游戏用**整条**灯带（`WSGAME_MAX_LEDS = WS2812_LED_NUM`）：物理索引 = 逻辑索引，只在
  `WSGAME_REVERSE_DIR = 1`（灯带装反）时由 `app_wsgame.c` 的 `led_index()` 镜像一下。
  按键灯是**另一条**数据线（PC4，见 3.3 节），与主灯带上的游戏画面互不覆盖。

* 节奏：运输带每 `WSGAME_TRACK_STEP_MS` 整体挪一颗灯（走完全程 = 该值 × 灯数）；远端口子每
  `WSGAME_SPAWN_MS` 补一颗，所以相邻两颗的间距 = `WSGAME_SPAWN_MS` ÷ `WSGAME_TRACK_STEP_MS` 颗灯，
  场上同时有十几二十颗。默认值见 `bsp_config.h` 第 10 节。
* 子弹每 `WSGAME_SHOT_STEP_MS` 飞一颗灯（飞到远端 = 该值 × 灯数），最多同时 `WSGAME_MAX_SHOTS` 颗；
  连点按键可以连发。
* **装机方向反了**（看着像往外跑）不用改接线：把 `bsp_config.h` 的 `WSGAME_REVERSE_DIR` 改成
  `1U` 即可 —— 只镜像渲染索引，逻辑完全不变。

**按键 / 按键灯映射**

| 按键 | 引脚 | 发射颜色 | 按键灯（主灯带最前面 4 颗，见 3.3 节） |
|---|---|---|---|
| Key1 | PA0 | 蓝 | 第 1 颗：常亮蓝（发射时闪一下） |
| Key2 | PA1 | 绿 | 第 2 颗：常亮绿（发射时闪一下） |
| Key3 | PA2 | 紫 | 第 3 颗：常亮紫（发射时闪一下） |
| Key4 | PA3 | — | 第 4 颗：运行指示（亮 = 运行中） |

* **Key4 短按 = 开始 / 暂停**，不用串口也能开局（也可以在 `app_wsgame.h` 里把
  `WSGAME_KEY_BLUE/GREEN/PURPLE/START` 改成别的键）。
* 颜色键只认 `KEY_EV_DOWN`（按下立刻发一颗），松手 / 长按保持都不会补发。
* 按键亮度和三色值在同一处：`WSGAME_KEYLED_LEVEL`（取值见 `bsp_config.h` 第 10 节，怕刺眼 / 怕被看成一片白就调小）、
  `WSGAME_BLUE_* / GREEN_* / PURPLE_*`（色块、子弹、按键灯共用）。
* **按键灯平时就是常亮的**：第 1/2/3 颗 = 蓝 / 绿 / 紫（和场上的三色同一组值、同一个亮度系数），
  第 4 颗 = 运行指示（游戏在跑才亮）。上电（`app_cmd_init()`）和游戏停止后都调
  `wsgame_keyled_idle()` 刷这个"常亮本色"，**不再有"按下点亮 / 松开熄灭"的反馈** ——
  想让按下去有反馈，在 `app_cmd.c` 的 `app_key_callback()` 里自己加 `keyled_set_color()`。
* 若按键灯的物理顺序与 Key1~Key3 不一致（例如第 1 颗灯焊在 Key2 下面），改
  `app_wsgame.c` 里 `keyled_apply()` / `wsgame_keyled_idle()` 的索引即可（"按键号 = 灯号"）。

**声音（WT2003HX 语音模块，见 3.2 节与 `bsp_config.h` 第 8/8.1/10 节）**

* **背景音循环**：开局先把模块设成"单曲循环"——帧就是 **`7E 04 AF 01 B4 EF`**（`AF` 数据 `01`，
  校验码 = 04+AF+01 = B4），再按索引点播 `WT2003_BGM_INDEX`（`9D`，帧 `7E 05 9D 00 01 A3 EF`，背景音文件 = `0007.mp3`）；**收局先发 `AF 00` 取消循环，
  再发 `AA` 停止播放**（`7E 03 AA AD EF`）。对应驱动接口 `wt2003_set_mode(WT2003_MODE_SINGLE_LOOP)` /
  `wt2003_stop()`。关机（`POWER OFF`）也会先取消循环并停掉背景音，免得盖住关机提示音。
* **三种音效（发射 / 打中同色 / 未消除）有两种发法**，用 `WSGAME_SFX_MODE` 选（`bsp_config.h` 第 10 节）：
  * `0` **插播**（现用）：发 **`7E 06 B1 <标示字> <曲目高> <曲目低位> <校验码> EF`**（例 外挂 Flash
    曲目 3 → `7E 06 B1 00 00 03 BA EF`），**叠加**在正在播的背景音上放，背景音不停、也不重头。
    标示字取第 8 节的 `WT2003_INSERT_FLAG`（**`00` = FLASH / 外挂 SPI Flash【现用】** /
    `02` = U 盘，见手册 4.1.2.14）；曲目号 = 文件在**该介质根目录**的索引
    （外挂 Flash 上：1 发射 / 2 消除 / 3 未消除）。
  * `1` **打断式**（备选，本模块已不用）：音效走 `9E` 按文件名点播（`0008`/`0002`/`0009`），**背景音会被顶掉**，
    `WSGAME_SFX_LEN_MS` 毫秒后自动 `AF 01` + 重播 `0007` 把背景音接上 —— 只用已验证的 `9E`/`AF`，
    代价是**背景音乐会重头开始**（音效越短越听不出来）。名字用 `WT2003_FILE_SHOT/_CLEAR/_MISS`。
  两种模式的索引都在第 10 节：`WSGAME_SFX_SHOT_INDEX`(1) / `_CLEAR_INDEX`(2) / `_MISS_INDEX`(3)
  （外挂 SPI Flash 上按放入顺序）。
* **背景音什么时候点**：开局后等 `WSGAME_BGM_DELAY_MS`（默认 4000ms）再点 —— 让上电的开机提示音
  `0006` 先播完，避免"模块正在播放时收到命令被丢掉，背景音一次也起不来"。
* **未消除音效什么时候响**：① 色块走到近端没被消掉（`MISS`）；② **子弹撞上“异色”灯**（`BLOCK`）也算没消掉，
  同样补一声未消除音效。两种情况下都不会得分。
* **发射那一发如果贴着近端异色灯**：子弹出膛即撞，这时只响“未消除”，不再叠加发射音（避免两声打架）。
* 可调开关（都在 `bsp_config.h` 第 10 节末尾）：`WSGAME_SOUND_ENABLE`（总开关）/
  `WSGAME_BGM_ENABLE` / `WSGAME_SFX_ENABLE` / `WSGAME_BGM_LOOP`（1 = 用模块单曲循环）/
  `WSGAME_BGM_LEN_MS`（>0 = 不管模块，按曲长自己重发）/ `WSGAME_BGM_DELAY_MS`（开局后多少 ms 才点
  背景音，默认 4000）/ `WSGAME_SFX_MODE`（0 = 插播（现用）/ 1 = 打断式）/ `WSGAME_SFX_LEN_MS`
  （模式 1 的音效时长，默认 600ms —— 按音效实际长度调大一点，免得音效没放完背景音就抢回来）/
  `WSGAME_SFX_GAP_MS`（连点最小间隔 80ms）/ `WSGAME_BGM_VOLUME`（`0xFF` = 不动音量）/
  `WSGAME_SFX_*_INDEX`（三个音效曲目号）。
* 单独试听：串口 `VNAME 0007` / `VNAME 0002`（`VOL 20` 调音量），
  音效插播用 `VINS 1` / `VINS 2` / `VINS 3`（可选第 2 个参数 = 标示字，可临时换：`VINS 1 2` = 按 U 盘试，不用重新编译），
  `VSCAN 1 3` = 把索引挨个插播一遍，用耳朵确认"几号 = 什么声音"；
  发/收帧看 `WTTX` / `WTRX`（`WT2003_TRACE = 1`，默认开）——开局应看到 `WTTX 7E 04 AF 01 B4 EF`
  + `WTTX 7E 05 9D 00 01 A3 EF`，
  打一枪应看到 `WTTX 7E 06 B1 00 00 01 C8 EF`（标示字/曲目号随配置变）。
* **背景音/音效完全不响的排查顺序**见 3.6 节最后几条（`VNUM` 看文件在不在 → `VNAME 0007` 单点 →
  `VINS 1` / `VINS 1 2` / `VINS 1 255` 试插播 → `VNAME 0008/0009/0002` 听音效文件本身）。
  注意三点：① 开机音 `0006` 与背景音走的是**同一条 `9E` 命令**（`0007` 能响 = 命令没写错）；
  ② `main.c` 的 `wsgame_init()` 必须被调用，否则游戏不开局、一帧声音都发不出去；
  ③ 模块"正在播放"时收到的命令可能被丢掉 → 背景音靠 `WSGAME_BGM_DELAY_MS` 等开机音播完再点；
  ④ 音效插播（`0xB1`）不响先查**标示字**：三个音效在外挂 Flash 上 → 必须是 `00`(FLASH)。
     `WT2003_INSERT_FLAG` 配错（比如写成 `02` 指向 U 盘、而盘上没这三个文件）就没声。
* 注意：音频命令发得太密模块会丢帧，驱动强制两条命令间隔 ≥ `WT2003_CMD_GAP_MS`（30ms），
  所以"点音效"这一下最多会把灯光任务卡住几十毫秒（画面会有一帧的小顿），受不了就把音效间隔调大
  或把音频请求挪到语音任务里发。

**碰撞与判定**

```
    近端(0)                                                远端(灯数-1)
      │  每 SPAWN 在远端补一颗, 前一颗没消掉就紧跟其后          │
      │   ◄── 整条每 TRACK 往近端挪一格 ◄──                     │  ●绿 ●紫 ●蓝 ●绿 ●紫 …
  按 Key2 ─►  ●绿 ──►(每 SHOT 飞一颗)──► 撞上 ●绿 → 两颗一起消失(白闪+1分)
                                          撞上 ●蓝/紫 → 打穿继续飞(默认; 只有 WSGAME_SHOT_PIERCE=0 才消失)
      ● 走到 0 还没被消掉 → 漏掉(计数, 近端灰白微亮一下)后消失
```

> 图里 `SPAWN / TRACK / SHOT` = `WSGAME_SPAWN_MS` / `WSGAME_TRACK_STEP_MS` / `WSGAME_SHOT_STEP_MS`，
> `白闪 / 微亮` 的时长 = `WSGAME_HIT_MS` / `WSGAME_MISS_MS`（数字都在 `bsp_config.h` 第 10 节）。

* 判定在**每一格**都做：子弹飞到某格、或灯挪到子弹所在格，都算撞上。
* **同色必消**（一发子弹只消一颗）；**异色打穿**（默认 `WSGAME_SHOT_PIERCE = 1`）：撞上不同色的灯什么都不做，子弹继续往外飞（这样"按下颜色键就一定能看见一颗灯飞出去"，不会被近端的异色灯堵在炮口），
  色块原地不动、不得分，也不会挡住后面飞来的同色子弹（`WSGAME_SHOT_PIERCE = 0` 的**老行为**才会这样：串口打一行 `BLOCK`）。
* 一发子弹从索引 0 出发，`pos >= WS2812_LED_NUM`（越过末位）就收回；近端最外那颗（索引 0）上也照样能打 ——
  按下按键的瞬间就判一次（同色的话出膛即消，白闪看得见；异色默认打穿）。

**参数**（全部集中在 `bsp_config.h` 第 10 节，改完重新编译即可）

| 宏 | 作用 |
|---|---|
| `WSGAME_AUTOSTART` | 1 = 上电直接开局；0 = 上电跑 `COMET`，用 Key4 / `GAME START` 开局 |
| `WSGAME_MAX_LEDS` | 游戏作用的灯珠数（默认 = `WS2812_LED_NUM`，铺满整条；按键灯走 PC4 另一条线，不冲突） |
| `WSGAME_TRACK_STEP_MS` | 运输带速度：每挪一颗灯的毫秒数（**越大越慢**；可调范围 `WSGAME_TRACK_STEP_MIN`~`MAX`） |
| `WSGAME_SPAWN_MS` | 远端口子：每多少毫秒冒一颗新灯 —— **必须 ≥ 3×`WSGAME_TRACK_STEP_MS`**（间距 = 本值 ÷ 节拍），比这个小色块会连成一条"实心墙"（范围 `WSGAME_SPAWN_MIN`~`MAX`） |
| `WSGAME_SHOT_STEP_MS` | 子弹速度：每飞一颗灯的毫秒数（**越小越快**；范围 `WSGAME_SHOT_STEP_MIN`~`MAX`） |
| `WSGAME_MAX_SHOTS` | 同时最多几颗子弹（连点上限） |
| `WSGAME_SHOT_PIERCE` | 1 = 子弹打穿异色灯（**默认**：按下颜色键就一定看得见一颗灯飞出去）；0 = 老行为，撞上异色灯子弹就地消失 |
| `WSGAME_SFX_SHOT_ENABLE` | 发射音效开关：**0 = 按颜色键不出声（当前值）**，消除 / 未消除音效照旧；1 = 出"发射"声 |
| `WSGAME_HIT_MS` / `WSGAME_MISS_MS` | 命中白闪 / 漏掉时近端提示的时长 |
| `WSGAME_KEYLED_FLASH_MS` / `WSGAME_KEYLED_BLINK_MS` | 发射时按键灯闪烁时长 / 闪烁周期 |
| `WSGAME_FRAME_MS` | 画面刷新周期 |
| `WSGAME_BLUE_*` `WSGAME_GREEN_*` `WSGAME_PURPLE_*` | 三色 RGB（灯、子弹、按键灯共用同一组值） |
| `WSGAME_KEYLED_LEVEL` | 按键灯三色的亮度折扣 |
| `WSGAME_AVOID_REPEAT` | 1 = 相邻两颗不同色 |
| `WSGAME_SEG_SCORE` | 用 4 位数码管显示得分（命中 +1） |
| `WSGAME_TRACE` | 从 ESP32 串口打 `WSGAME ...` 调试行；正式出货想静默改成 0 |

> 本表只说每个宏"干什么"：**数值/开关档位一律看 `bsp_config.h` 第 10 节**，本文档不抄。

**怎么确认逻辑跑起来了**（`WSGAME_TRACE = 1` 时，ESP32 串口会看到）

```
WSGAME START step=100ms spawn=600ms shot=15ms maxshots=8   上电/开局那一下（游戏接管灯带）
WSGAME SPAWN color=GREEN idx=119 blocks=1                  远端冒出一颗新灯
WSGAME SHOT color=GREEN shots=1                            按 Key2 发射一颗绿子弹
WSGAME HIT color=GREEN idx=87 score=1 left=3               打中同色 -> 两颗消失 + 数码管 +1
WSGAME MISS near-end misses=1 left=2                       没消掉, 走到近端 -> 漏掉(不扣分)
WSGAME SHOT full color=BLUE max=8                          天上子弹已满: 这一发不响应
WSGAME BLOCK my=GREEN cell=BLUE idx=61 shots=0              撞上异色: 子弹自己消失(色块留着)
WSGAME STOP score=5 hits=5 misses=2                        收局(GAME STOP / 关机)
```

* 数码管：开局显示 `0000`，每命中一次 +1。
* 随时可查快照：`GAME` → `GAME RUN state=RUN blocks=17 shots=2 step=100ms spawn=600ms shot=15ms score=3 hits=3 miss=1 spawned=21`。
* 手感调整（都不用重新编译）：`GAME SPD 200`（运输带慢下来）、`GAME SPAWN 900`（灯稀一点）、
  `GAME SHOT 10`（子弹快一点）。

**已知取舍**

* 漏掉**不扣分**、也不结束；想加惩罚 / 连击，只改 `app_wsgame.c` 的 `shot_check()` /
  `track_tick()`（漏掉那一段）。
* 运输带**填满整条**时远端口子会暂停补灯（等前面消掉 / 漏掉腾位置），不会覆盖已有的灯。
* **“按了颜色键却看不到发射出去的灯”怎么查**：① 先看 `GAME` 的 `shots=` 和串口有没有 `WSGAME SHOT` 行
  —— 没行就是**天上子弹已满**（`WSGAME SHOT full`，`WSGAME_MAX_SHOTS` 上限）或按键事件没上来；
  ② 有 `WSGAME BLOCK` 行 = 子弹一出膛就撞上近端的异色灯（**老行为**，把 `WSGAME_SHOT_PIERCE` 设回 1 即可）；
  ③ 有 `WSGAME SPAWN` 但场上是**连成一片**的色块 = `WSGAME_SPAWN_MS` 太接近 `WSGAME_TRACK_STEP_MS`
  （间距 ≤ 1 颗），运带变成"实心墙"，近端永远有灯把炮口堵住 —— 把 SPAWN 改成节拍的 3 倍以上。
* 得分直接写数码管；若同一时刻手发 `DISP` 命令，最多一帧画面被搅乱（下一次计分自动恢复）。
* 游戏在跑时，`FX` / `FILL` / `LED` 这几个"直接改灯带"的命令会**先停止游戏**再执行
  （应答里带 `(game stopped)`），否则命令生效一帧（`WSGAME_FRAME_MS`）后就被游戏的下一帧覆盖了；
  `BRT` 不用停游戏（亮度对游戏同样生效，游戏下一帧就用新亮度重画）。
* 游戏与效果层共用同一条灯带，但同一时刻只有一个在画：开局时效果层被切到 `LED_FX_OFF`,
  收局时按开局前记录的效果还原（上电本来就是 `OFF` 时按 `COMET` 还原）。

## 4. 远程命令协议（`app_cmd`，示例业务代码）

WiFi 端（ESP32-C3）透传 ASCII 文本行，**命令不区分大小写**，以 `\n` 或 `\r\n` 结束；
发完不跟换行也行（静默 `ESP32_LINE_IDLE_MS`=100ms 后按整行处理，见 3.5 节）：

| 命令 | 说明 | 应答 |
|---|---|---|
| `PING` | 连通性测试 | `+PONG` |
| `STATUS` / `?` | 查询状态 | `STATUS fx=.. brt=.. spd=.. rgb=.. keys=0x.. up=.. frame=.. rx=.. ovf=..` |
| `UART` | **串口链路自检**：计数器 + `last=`（最近真正解析过的整行） | `UART rx=.. lines=.. buf=.. pend=.. raw=..` / `UART ovf=.. err=.. drop=.. long=..` / `UART cap=.. lost=.. wraps=.. size=..` / `UART last="KEYLED 0 255 0 0"` |
| `UART RAW <0\|1>` | 1 = 收到的每个字节都打一行 `RX hh c`（查链路有没有丢/多字节；调试完记得关） | `OK UART RAW 1` |
| `UART DUMP [n\|ALL]` | **打印原始接收缓冲**（十六进制 + ASCII + `FLG` 标记行），默认最近 128 字节，`ALL` = 整个缓冲 | `CAP total=.. show=.. idx=..` / `CAP 0001 4B 45 59 4C 45 44 20 ...` / `FLG      L  .  .  .  .` / `OK UART DUMP` |
| `FILL r g b` | 整条灯带单色（游戏在跑时先停止游戏） | `OK FILL r g b` |
| `LED start count r g b` | 指定区段上色（同上） | `OK LED start count` |
| `FX n` | 切换效果 0~6（OFF/SOLID/RAINBOW/COMET/BREATHE/BLINK/CHASE）（同上） | `OK FX n NAME` |
| `BRT 0..255` | 亮度（游戏与效果层都生效） | `OK BRT v` |
| `SPD 200..8000` | 动画周期(ms) | `OK SPD v` |
| `GAME` / `GAME STATUS` | **消消乐**：查运行状态/场上灯数/在飞子弹/三个速度/得分 | `GAME RUN state=RUN blocks=17 shots=2 step=100ms spawn=600ms shot=15ms score=3 hits=3 miss=1 spawned=21` |
| `GAME START` / `GAME STOP` | 开局（重开一局，分数清零）/ 收局（清屏，灯带交还效果层） | `OK GAME START (step=100ms spawn=600ms shot=15ms maxshots=8)` / `OK GAME STOP (strip back to fx)` |
| `GAME SPD <ms>` | **运输带速度**：灯每挪一颗灯的毫秒数（越大越慢；范围 `WSGAME_TRACK_STEP_MIN`~`MAX`） | `OK GAME SPD <ms>` |
| `GAME SPAWN <ms>` | **远端口子**：每多少毫秒冒一颗新灯（范围 `WSGAME_SPAWN_MIN`~`MAX`） | `OK GAME SPAWN <ms>` |
| `GAME SHOT <ms>` | **子弹速度**：每飞一颗灯的毫秒数（越小越快；范围 `WSGAME_SHOT_STEP_MIN`~`MAX`） | `OK GAME SHOT <ms>` |
| `VOL 0..31` | 设置音量（`AE`） | `OK VOL 20 (0xAE)` |
| `VNUM` | 查询模块里的文件总数（`C4`）：几毫秒后由驱动解析，新结果看串口 `WTRXCOUNT` 行 | `OK VNUM last=6 (0xC4, new answer on WTRXCOUNT)` |
| `VPLAY 1..65535` | 按 **模块当前盘的根目录索引**播放（`9D`，校验码自动算） | `OK VPLAY 1 (0x9D by root index)` |
| `VINS <index> [flag]` | **插播**（`B1`）：叠在正在播的背景音上放，背景音不停；帧 = `7E 06 B1 <标示字> <高> <低> <ck> EF`，标示字缺省取 `WT2003_INSERT_FLAG`（**`00` = FLASH / 外挂 SPI Flash【现用】** / `02` = U 盘，手册 4.1.2.14），排查时可临时给第 2 个参数；**`flag = 255` = 不带标示字的 2 字节形式**（`7E 05 B1 <高> <低> <ck> EF`）。⚠ 三个音效在外挂 Flash 上，标示字必须是 `00` | `OK VINS 1 (0xB1 insert, flag=0x00)` / `VINS 1 2` → `flag=0x02` / `VINS 1 255` → `2-byte form` |
| `VSCAN [from] [to] [gap_ms] [flag]` | 从 `from` 到 `to` **挨个插播一遍**（默认 `1`..模块文件总数、间隔 1200ms），用耳朵找出"哪个索引/标示字才是要的那段音频"；一次最多 21 个，**执行期间串口安静一阵** | `OK VSCAN 1..12 gap=1200ms flag=0x00 (count=6)` + 每个 `VSCAN playing n` |
| `VMODE <0..3>` | 直接发 **指定播放模式**（`AF`）：`0` 单曲 / `1` 单曲循环 / `2` 全部循环 / `3` 随机；排查"背景音不响是不是 `AF 01` 引起的"（`VMODE 1` 后再 `VNAME 0007`） | `OK VMODE 1 (0xAF) loop-on` |
| `VOICE <file4>` / `VNAME <file4>` | 按 **文件名**播放（`9E`）：名字必须 4 字符且放 U 盘根目录，如 `VOICE 0001`；不带宽参时列出 `WT2003_FILE_xxx` 这套名字 | `OK VOICE "0001" (0x9E by file name)` |
| `VRAW <hex…>` | **原样发任意帧**给模块（`wt2003_send_raw()`，复刻退役的 `WTRAW`）：字节自己拼好，首字节 `7E`、末字节 `EF`，一次 5~16 字节；也接受 `0x7E` / 空格 / 逗号 / 冒号分隔；校验码**不代算**（帧格式与算法见 3.6 节；故意发错码做对照也行 —— 错码模块不回帧） | `VRAW 7E03C4C7EF` → `OK VRAW 7E03C4C7EF (5 bytes)`；`VRAW 7E 06 B1 00 00 08 BF EF` → `OK VRAW ... (8 bytes)` |
| `DISP 1234` | 数码管显示（≤4 字符） | `OK DISP ...` |
| `KEYLED <0..3|ALL> r g b [周期ms]` | 按键灯（带周期即闪烁）；走 PC4 独立数据线，软件时序（见 3.3 节） | `OK KEYLED` |
| `KEYLED DIAG` | 按键灯诊断：四段时序（目标 ns / 实际计数拍数 / 扣掉的固定开销）+ `meas`（最近一帧实测−目标，单位拍）+ `tim=`（1 = 定时器中断发帧）`frames=`（中断已发帧数）+ `invert=` `calib=` `fclk=` + 线路自检 `line low/high` + 每路 `set=`（设定色）/`out=`（实际输出色） | 多行 `KEYLED ...` |
| `KEYLED T0H\|T0L\|T1H\|T1L <ns>` | 实时改四段电平（`0` = 用回配置默认值），改完立即重发一帧，不用重编 | `OK KEYLED T0H x T0L y T1H z T1L w` |
| `KEYLED INVERT <0\|1>` | 数据线是否反相（线上串了反相器 / 三极管时用 `1`） | `OK KEYLED INVERT x` |
| `KEYLED INIT [n]` | 连发 `n` 帧**全灭**（默认 `KEYLED_INIT_FRAMES` 帧）：现场重来一次上电那几帧，把被噪声/上一个项目锁存成白色的灯珠压回全灭，再发颜色命令 | `OK KEYLED INIT 3 frames (all off)` |
| `HEARTBEAT ms` | 周期心跳上报（0=关闭） | `OK HEARTBEAT ms` |
| `POWER OFF` | 远程关机 | `OK POWER OFF`（随后断电） |

STM32 主动上报：

```
EVT KEY <id> <DOWN|UP|SHORT|LONG|HOLD> <ms>
EVT POWER SHORT
READY LEDAnipop fw=1.0 led=120        (上电第一条)
HB <uptime_ms> <fx> <brt>             (开启 HEARTBEAT 后)
WSGAME START/SPAWN/SHOT/HIT/MISS/BLOCK/STOP (消消乐, WSGAME_TRACE=1 时, 见 3.10)
```

按键灯的本地联动：**第 1/2/3 颗平时就常亮蓝 / 绿 / 紫（和消消乐里三颗颜色键灯同色），不再随按键亮灭**，
上电和游戏停止后都由 `wsgame_keyled_idle()` 刷新（`app_cmd_init()` 里调一次）；
**消消乐运行时按键灯由 `app_wsgame` 接管**（多一个"发射闪烁"提示）。
想要"按下点亮"的反馈，在 `app_cmd.c` 的 `app_key_callback()` 里自己加 `keyled_set_color()`。

   RAM 占用约 **21.3 KB / 48 KB**（灯带缓冲约 6.6 KB，4 个任务各 1KB 栈，其余为 RTX 内核数据）。
3. 初始化顺序（见 `main.c`，顺序不要随意调整）：
   `bsp_util_init()` → `bsp_time_init()` → `bsp_rtos_init()` → `power_init()` → `ws2812_init()` →
   `led_fx_init()` → `keyled_init()` → `hc595_init()` → `esp32_init()` → `wt2003_init()` →
   `drv_key_init()` → `app_cmd_init()` → `app_task_start()`。
   > `bsp_rtos_init()` 必须在"会创建锁/队列"的 `*_init()` 之前；`app_task_start()` 必须在全部
   > 硬件初始化 + `app_cmd_init()` 之后（它负责创建任务并启动调度器）。
4. `app_task_start()` 启动 RTX 后不再返回；把 `BSP_USE_RTOS` 改成 0 时它立刻返回，由 `main.c`
   末尾的主循环依次调用各 `*_process()`，最后 `__WFI()` 休眠（任意中断都能唤醒）。
5. 用 VSCode 编辑时已配好"保存即格式化"：规则在工程根目录 `.clang-format`（Allman 大括号 +
   文件末尾留一个换行），开关在 `.vscode/settings.json`（`editor.formatOnSave`）。想手动把整个
   工程排一遍版：`clang-format --style=file -i Src/*.c Inc/*.h`。

> 提示：源文件是 UTF-8 编码。若 uVision 编辑器里中文注释显示乱码，请在
> `Edit → Configuration → Editor → Encoding` 选择 **UTF-8**（armcc/armclang 编译按 UTF-8 处理，不受影响）。

## 6. 已知的假设与限制（请按实物核对）

1. **芯片**：按工程现有配置为 **STM32F103RCT6**（你描述的 "STM32g4F103RCT6" 应是笔误）。
   若实际是 STM32G4，本目录的 StdPeriph 代码不能直接用，需要换成 HAL/CubeMX 工程。
2. **WT2003HX 串口协议**：已按《WT2003HX 芯片》手册对齐（帧 `7E 长度 命令 数据 校验码 EF`，
   长度含自身；命令码见 3.6 节）。固件命令码不同时，只改 `drv_wt2003h.h` 的 `WT2003_CMD_*`。
3. **PC3 电源自锁极性**：`POWER_HOLD_ON_LEVEL=1`（高电平维持供电），低有效时改成 0。
4. **按键灯走 PC4 独立数据线（软件位时序）**：四段电平由 `bsp_config.h` 第 5 节的 `KEYLED_*` 给，
   默认值就是第 4 节 `WS2812_*` 换算来的（主灯带时序已实测好用，两条支路共用同一套时间）；
   改主灯带时序时把 `KEYLED_*` 一起改（反之亦然）。按键灯颜色不对时先 `KEYLED DIAG` 看四段实测、
   `line low/high` 自检与每路 `set/out`，再用 `KEYLED T0H/T1H/T0L/T1L <ns>` 现场扫（见表 3.3）。
   游戏层用的是**整条**主灯带（`WSGAME_MAX_LEDS = WS2812_LED_NUM`），与按键灯那条线互不影响。
5. **WS2812 帧间复位**已按规格书取值（`WS2812_RESET_US`）；只有确认灯珠能吃 50µs 复位、想提高帧率时才往小调。
6. 按键**组合键**未实现，需要时在 `drv_key_process()` 里加一层判定即可。
7. 数码管是**静态显示**（4 片 595 各管一位），没有动态扫描，因此没有刷新中断。

## 7. 联调建议

| 现象 | 检查点 |
|---|---|
| 灯带不亮 / 只有第一颗亮 | 先敲 `STATUS` 看 `frame=` 是否在涨（涨→固件侧没问题，直接查硬件）；再按 **3.2.1 节**的 3 步自检 + 现象对照表逐条对号入座 |
| 灯带颜色错位、闪烁 | `WS2812_T0H_NS/T1H_NS`；帧间复位时间；供电与地线是否够粗 |
| 按键不响应 | 内部上拉是否生效（`GPIO_Mode_IPU`）；`drv_key_process()` 是否在主循环被调用 |
| 按键灯发白 / 串色 / 颜色不对 | 走 PC4 软件时序（见 3.3 节）：先 `KEYLED DIAG` 看四段实测与 `line low/high`（驱动低/高时引脚读回应为 `0`/`1`），再用 `KEYLED T0H 250` / `KEYLED T1H 700` 之类逐项扫；发白多为 `0` 码被读成 `1` 码（高电平偏长）；整条不亮先查 PC4 → DIN 接线、共地、灯带供电与电平转换（**3.2.1 节**第 3 步第 1 条） |
| 串口收不到命令 / 回`ERR UNKNOWN`一串乱码 | 先敲 `UART` 看四个东西：① **`rx` 一点也不涨** = 命令根本没到 STM32（查 PA9/PA10 接线、ESP32 桥接固件是否在跑、是否共地；ESP32 侧的回环测试只证明桥接芯片那一段通，见 3.5 末尾）；② **`rx` 涨、`lines` 不涨** = 字节到了但一直是半条行（上位机不发 `\r\n` 时靠 `ESP32_LINE_IDLE_MS` 收尾，确认通信任务在跑）或数据太长被 `long` 丢掉；③ **`err`/`drop`/`ovf` 在涨** = 线上有错或被关中断挤掉字节（`err` 涨 = 噪声/波特率/被高优先级中断压住；`ovf` 涨 = 环形缓冲满，任务太久没被调度）；④ **`lost` 涨** = DMA 窗口被覆盖，`esp32_process()` 没被按时调用（任务被饿着）。再敲 `UART DUMP 128`，把十六进制和上位机实际发的字节**逐字节对**，一眼就能看出是"丢字节"还是"多字节"。波特率 115200 8N1；`INO\ESP32C3\ESP32C3.ino` 桥接固件用批量转发版本（见 3.5） |
| 串口**老是少 1 个字母**（命令偶尔/经常残缺，`ERR UNKNOWN` 里能看到半截命令） | 这是"收数被挤掉"的典型：USART 只有 1 个字节的接收寄存器，只要 87µs 内进不去接收中断，这个字节就永久丢失。本工程已把接收改成 **DMA1_Channel5 环形搬运**（`ESP32_RX_USE_DMA = 1`）并把中断优先级排成 `ESP32_UART`(0) **高于** `WS2812_DMA`(1)（见 3.5）。逐条核对：① `bsp_config.h` 第 7 节 `ESP32_RX_USE_DMA` 是否为 1；② 第 1 节两个 `BSP_IRQ_PRIO_*` 有没有被改回去；③ `APP_TASK_COMM_PERIOD_MS` 是否为 10ms（DMA 方式没有中断唤醒，它就是这个命令的最大响应延迟）；④ `UART` 里 `lost` 是否为 0、`err` 是否不再涨；⑤ `UART DUMP` 里丢的那个字节是否带 `E`/`D`/`O` 标记。若把 `ESP32_RX_USE_DMA` 设回 0，就必须保证没有别的地方长时间不给串口进中断（按键灯发帧那 120µs 正是其中之一，所以驱动里保留了那条闸门） |
| 数码管顺序反了 | `HC595_DIGIT_REVERSE`（=1 倒序，本板默认值，`bsp_config.h` 第 6 节）、`hc595_digit_map[]` |
| 上电自锁不住 | `POWER_HOLD_ON_LEVEL` 极性、PC3 与硬件自锁电路的接法 |
| WT2003 完全没声音、`WT2003_TRACE=1` 下连一行 `WTRX` 都没有 | 模块**一句都没回**：PB10→模块RXD、PB11←模块TXD、**共地**、9600 8N1、模块是否被设成串口控制模式；用 `VRAW 7E03C4C7EF` 发一帧最简单的查询，仍无回帧就是链路/模式问题 |
| WT2003 串口能看到 `WTRX ...` 回帧但仍无声 | UART/协议/接线已通 → 转查**音频侧**：模块在盘上到底认没认到文件、文件名是不是 4 个字符、功放/喇叭、音量；先敲 `VNUM`（结果看 `WTRXCOUNT` 行，`0` = 没认到文件），再用 `VOICE 0001` / `VPLAY 1` 点播（见 3.6 节） |

调试灯带时序时，建议先用 `led_fx_set(LED_FX_SOLID)` + `ws2812_set_pixel(0,255,0,0)` 确认底层时序正确（只有第一颗红、其余灭），再开动画效果。

* 若你的板子不方便用 TIM2，可以把 `bsp_time.c` 里的 `BSP_TIME_TIM` 换成 TIM3/TIM5（注意别和灯带的 TIM4 冲突）。

## 8. WT2003 语音模块：历史与留档

第 8 节以前记的是"语音链路排查"的全过程（38 步上电自检、返回码取证、`A0/A6/A7` 对照、

现在按手头《WT2003HX》手册只保留 4 条命令（见 3.6 节），其余全部退役：

* 退役的代码（上电自检序列、Key 口、按文件名轮播、其它命令封装）与退役的调试命令
  （`WTRAW`〔**已由第 4 节的 `VRAW` 回归**〕/ `WTPROBE` / `WTSTOP` / `WTST` / `VCHECK` / `VOUT` / `VQRY` / `VPLAY6` /
  `VPLAY0` / `VNAMEON` / `VNAMEOFF` / `VKEY` / `VSTOP` / `VPAUSE` / `VNEXT` / `VPREV`）
  + 旧命令表 + 历年排查日志：`Doc/WT2003_退役命令与自检备份.md`；
* 精简前的完整源码（改动前原件，确认无误后可删）：`Doc/orig_20261005/`。

新固件的排查姿势（比那时简单得多，不用重烧也不用挂调试器）：

1. `bsp_config.h` 的 `WT2003_TRACE` 默认就是 `1`：从 ESP32 串口看 `WTTX/WTRX/WTRXCOUNT`；
2. `VNUM` 查文件总数 —— `WTRXCOUNT 0` 说明模块在盘上看不到文件
   （U 盘没认到 / 文件名不是 4 个字符 / 不是根目录）；
3. `VOICE 0001` 按文件名点播（听声音）；`VPLAY 1` 按根目录索引点播；
4. `VOL 20` 试音量。命令码在 `bsp_config.h` 第 8 节的 `WT2003_CMD_SET_VOLUME`（默认 `0xAE`），
   万一手里的手册不是这条，**只改这一行**即可。

> 硬件侧的老经验仍然有效：喇叭必须接 **SPK+ / SPK−**（BTL 输出），一端接 GND 则永远无声。
