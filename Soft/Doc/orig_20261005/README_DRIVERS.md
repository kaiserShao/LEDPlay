# 灯带消消乐 —— STM32 驱动说明

> 目标芯片：**STM32F103RCT6**（256KB Flash / 48KB RAM，SYSCLK 72MHz）
> 工程：`LEDAnipop.uvprojx`（Keil MDK，StdPeriph Driver V3.6.0）
> 全部源文件为 **UTF-8** 编码，中断里只做最少的事；业务逻辑跑在 **Keil RTX 的 4 个任务**里，
> 也可以把 `Inc/bsp_config.h` 的 `BSP_USE_RTOS` 改成 0，一键退回"主循环轮询"的裸机版本。

## 3. 各驱动的关键设计

### 3.1 按键（`drv_key`）—— 中断里只做两件事
* EXTI 中断（由 `bsp_exti.c` 统一实现）只做：**记录时间戳 + 置标志位**。
* 消抖（`KEY_DEBOUNCE_MS`）、短按/长按（`KEY_LONG_MS`）判定、事件入队全部在 `drv_key_process()` 中完成，主循环每 1ms 调用一次即可。
* 事件队列：`KEY_EV_DOWN / UP / SHORT / LONG / HOLD`，用 `drv_key_get_event()` 取，或注册 `drv_key_set_callback()` 立即处理。
* 引脚无外部上拉 → `GPIO_Mode_IPU`（内部上拉），按下读取到低电平。

### 3.2 主灯带（`drv_ws2812`，`WS2812_LED_NUM` 颗）—— PWM + DMA 永不间断
* TIM4 输出 PWM，**1 个位 = 1 个 PWM 周期**（周期 = `WS2812_BIT_NS`，WS2812 家族就是 800kHz 档）：
  `0` 码 / `1` 码 = 两个不同的 CCR 值（由 `WS2812_T0H_NS` / `WS2812_T1H_NS` 换算），复位 → CCR=0。
* DMA1_Channel1 **循环模式**把 CCR 值不断写入比较寄存器，全程硬件搬运。
* 缓冲区分三段：前半帧 ｜ 后半帧 ｜ 复位段；每段的元素数由 `WS2812_LED_NUM`、`WS2812_BIT_NS`、
  `WS2812_RESET_US` 算出来（自检的 `WS2812ST cfg` 行会把 `leds/data/buf/bit/T0H/T1H/reset` 全打出来）。
* **半传输中断(HT)** 刷新前半帧、**传输完成中断(TC)** 刷新后半帧+复位段；
  每个中断的余量 = 半帧时间（≈ 半帧位数 × 位周期）→ 灯带数据永不断流。
* 应用层只改颜色缓冲并调用 `ws2812_show()`；中断在帧边界做一次快照，**整帧颜色一致**（不会撕裂）。
* 内存：PWM 缓冲 = 缓冲区位数 × 2 字节 + 颜色缓冲（双缓冲）。
* 亮度在中断里做缩放（`ws2812_set_brightness()`），Mobile 不需要额外内存。
* ⚠ 细节：由于 CCR 使用预装载（必须，否则数据位会出错），上电后的**第一帧会比正常帧多 1 个 0 位**，之后的所有帧都完全正确（复位段会重新对齐）。肉眼不可见。
* 帧间复位按供应商规格书取大于 280µs 的值（宏 `WS2812_RESET_US`；它换算成多少位、帧周期多少 ms，
  自检的 `WS2812ST cfg` 行会打印）：
  规格书表格写"大于 50µs"，但同一份规格书的时序图/数据刷新周期标的是 **≥280µs**，所以取在 280µs 以上
  （当前实际取值见 `WS2812_RESET_US`）。

#### 3.2.0 与供应商规格书（WS2812B）逐项对照

| 参数 | 规格书 | 本固件 | 判定 |
|---|---|---|---|
| VDD | 3.5 ~ 5.3V | 板载 +4.68V | ✓ |
| V_IH | **0.7×VDD**（4.68V → 3.28V；5V → 3.5V） | MCU 3.3V 直连 | ✗ 需电平转换（见 3.2.1 第 3 步第 1 条） |
| V_IL | 0.3×VDD | 0V | ✓ |
| T0H | 0.4µs ±150ns（250~550ns） | `WS2812_T0H_NS` | ✓ |
| T1H | 0.8µs ±150ns（**下限 650ns**） | `WS2812_T1H_NS` | ✓（旧值 600ns 低于下限 ✗，已改） |
| T0L | 0.85µs ±150ns（700~1000ns） | 位周期 − T0H | ✓ |
| T1L | 0.45µs ±150ns（300~600ns） | 位周期 − T1H | ✓（旧值 650ns 超上限 ✗，已改） |
| TH+TL | 1.25µs ±600ns | `WS2812_BIT_NS` | ✓ |
| RES | 表格写 >50µs，时序图/刷新周期写 **≥280µs** | `WS2812_RESET_US` | ✓ |

> "本固件"列只写宏名：**取值一律以 `bsp_config.h` 第 4 节为准**，本文档不抄具体数字；
> 换算出来的 ns / 定时器拍数由自检的 `WS2812ST cfg` 行打印 —— 所以调参数不需要改本文档。

* 三条"**代码没错也永远不亮**"的时序原因，都已按规格书消除：
  1. **T1H 只有 600ns**（< 下限 650ns）→ 1 码高电平太短，灯珠可能采成 0 码。
     现象：发 0xFF（全 1）过去，灯珠收到 0x00 → **一颗都不亮**。→ 现在取在规格书下限以上（`WS2812_T1H_NS`）。
  2. **帧间复位只有 60µs**（低于时序图的 280µs）→ 灯珠可能永远等不到"锁存"，
     上电后一直是灭的。→ 现在取大于 280µs 的 `WS2812_RESET_US`。
  3. 3.3V 直驱 5V 灯带，V_IH 不够（见上表）→ 必须电平转换。

#### 3.2.1 主灯带"从来不亮"排查（先分清"固件没发"还是"硬件没收到"）

**第 0 步（不用改代码、不用示波器）**：连上 ESP32 串口（USART1, 115200）敲 `STATUS`，只看 `frame=`：

| `STATUS` 现象 | 结论 | 下一步 |
|---|---|---|
| `frame=` 稳定均匀地涨（期望值 = 帧率，准确值看自检 `rate B` 行的 `healthy=`） | 固件侧完全正常：DMA 循环 + HT/TC 中断在跑，PB6 上**一定有** 800kHz 数据波形 | 别再改代码，直接查硬件（看下面"硬件 5 条"） |
| `frame=` **一直是 0** | DMA 没被触发 / 中断没进 → PB6 上没有任何数据 → 灯带必然全黑 | 查 `ws2812_is_running()`、`DMA1_Channel1_IRQHandler` 是否被别的模块 `DMA_DeInit` 掉、`ws2812_init()` 是否真的被调用 |
| `frame=` 涨得**很慢 / 乱跳** | 中断被长时间关闭（例如按键灯输出期间的 `KEYLED_LOCK_IRQ`）→ 帧率不足 | 典型现象是闪烁/拖尾，而不是全黑 |

顺带确认两个"程序里就能把灯关掉"的开关：`brt=` 不能是 0（`BRT 0` 会把所有颜色乘 0）；`fx=` 不能是 `OFF`（`led_fx_process()` 在 `LED_FX_OFF` 时直接 return，灯就是黑的），正常固件上电是 `COMET`。

**第 1 步：万用表直流档量 PB6（或灯带 DIN 焊盘）对 GND 的平均电压。**
800kHz 是连续数据流，直流档读到的是**占空比平均值**，所以：

| 命令 | PB6 平均电压 | 含义 |
|---|---|---|
| `FILL 0 0 0`（全黑） | ≈ VCC × 0 码占空比（占空比 = `WS2812_T0H_NS` ÷ `WS2812_BIT_NS`） | 有数据在输出 |
| `FILL 255 255 255`（全白） | ≈ VCC × 1 码占空比（占空比 = `WS2812_T1H_NS` ÷ `WS2812_BIT_NS`） | 有数据在输出，且明显比全黑高 = 数据确实在变 |
| 两个都 ≈ **0V** | 这条线没有信号：PB6 虚焊 / 数据线断 / 被短路到 GND | 分别量 MCU 的 PB6 焊盘和灯带的 **DIN** 焊盘，定位断点 |
| 两个都 ≈ **3.3V** | 引脚被拉高，或根本没配成复用输出（`GPIO_Mode_AF_PP`） | 查 `ws2812_init()` 是否被调用、PB6 上是否有外部电路把它顶住 |

（若 PB6 与灯带 DIN 之间加了电平转换/缓冲，把上表读数乘以 `VCC_转换器 / 3.3` 估算；
例如 4.68V 供电的 74LVC1G125：全黑 ≈1.5V、全白 ≈3.0V。）

**第 2 步：上电三步自检**（`Inc/bsp_config.h` → `WS2812_BOOT_SELFTEST = 1U` 后重新编译）。
上电后灯带依次：① 只有第 0 颗红 → ② 整条暗绿 → ③ 整条全白（每步 `WS2812_SELFTEST_MS`），
数码管同步显示 `0001/0002/0003`，ESP32 串口同步打 `WS2812ST …`。串口完整输出应该是：

```
WS2812ST cfg leds=120 data=2880 buf=3120 bit=1250ns T0H=400ns T1H=800ns reset=300us arr=90 ccr0=29 ccr1=58
WS2812ST 1/3 pixel0=red  ONLY first led should light
WS2812ST 2/3 all=dim green  (low current: tests 5V/GND)
WS2812ST 3/3 all=white      (max current: tests power drop)
WS2812ST rate A frame=1234 tim2=5678ms dwt=1
WS2812ST rate B frame=1490 tim2=6678ms frames=256 tim2_dt=1000ms (healthy=256@120led/3120bit)
WS2812ST done: frame=1500 running=1 brt=255 (see README 3.2.1)
```

* `cfg` 行 = **这一版固件实际生效的时序参数**（`bit=` 一位多少 ns、`T0H/T1H` 即 0/1 码高电平），
  末尾 `arr/ccr0/ccr1` = 驱动按实际时钟换算出来的定时器拍数，与同一行的 `bit=/T0H=/T1H=` 必须自洽
  （`arr` × 定时器计数周期 = `bit=`；`ccr0/ccr1` 对 `T0H=/T1H=`）。对不上就说明工程时钟配置
  （SYSCLK/PCLK1）与 `WS2812_BIT_NS` 不匹配。
* `rate A/B` 两行 = 中间夹一次 **1 秒忙等** 的 `frame` / `tim2` 快照，请配合 **PC 串口工具的时间戳** 一起看：
  * PC 上 A/B 两行的真实时间差 = 这个窗口到底有多久；`frames=` = 窗口内 DMA 完成了几帧 → 真实帧率；
  * 真实帧率对上自检 `rate B` 行给出的 `healthy=` → 定时器 / DMA / 中断 / 缓冲位宽在真机上全部确认无误，
    **这时灯带还全黑，就只剩硬件**；
  * `frames` 明显偏小或为 0 → 先查是否有别处长时间关中断，或 DMA 被停掉；
  * 若 PC 上"1 秒"实际走了更久、而 `frames × 帧周期` 正好等于真实耗时 → 帧周期本身是对的，
    只是 `bsp_delay_ms()` 的 DWT 忙等偏慢（纯软件问题，与灯带波形无关）。
* 本自检本身**不依赖任务/效果层**（此时 `app_task_start()` 还没跑、`fx` 还没设置），所以它全黑与 `fx=/brt=` 无关。

| 现象 | 结论 |
|---|---|
| 三步全黑（但串口 `WS2812ST` 行都在打） | 固件在发、灯带没收到 → 硬件：供电 / 共地 / **3.3V 电平** / DIN-DOUT 接反 / 灯珠型号 |
| 只有第 0 颗亮（且随步骤红→绿→白） | MCU → 第 0 颗通了（说明电平勉强够），第 0 颗 → 第 1 颗断了：首颗虚焊/灯带断裂，或波形畸变到第 1 颗就识别不了 |
| ① 只有第 0 颗，②③ 整条都亮 | 灯带链路完全正常 → 问题不在硬件，回到业务/效果层（`fx=` / `brt=` / `rgb=`） |
| ①② 正常，③（全白）才不亮 / 变暗 / 闪 | **供电能力不足**：线太细太长压降大、USB 口电流不够 → 加粗电源线、灯带**双端供电**、就近加 470~1000µF 电解电容 |
| 亮但颜色不对（红↔绿互换、整体错位） | 灯珠颜色顺序是 RGB 而非 GRB（改 `ws2812_encode()` 的字节顺序）；或颗数与 `WS2812_LED_NUM` 不符 |
| 整条随机闪、越靠后越乱 | 时序/复位不匹配：复位已按规格书取值（`WS2812_RESET_US`），仍乱就查 `WS2812_T0H_NS/T1H_NS`、线材压降与共地 |

**第 3 步：硬件上最容易"代码没问题也永远不亮"的 5 条**（按现场出现概率排序）：

1. **用 3.3V 去驱动 5V 灯带**：WS2812 的 V_IH 一般是 **0.7×VDD ≈ 3.5V**，STM32 的 3.3V 输出正好落在临界点，
   最典型现象就是"**一颗都不亮**"（或只有第 0 颗亮）。解决（任选其一）：
   ① 加 **74HCT245 / 74AHCT1G125**（5V 供电的 HCT/AHCT，输入阈值低）做电平转换；
      本板实测方案：**SN74LVC1G125DBVR**（A=PB6、Y→灯带 DIN、OE 接 GND=使能）。
      两个关键条件：**VCC 必须接灯带那一侧的电源（本板 +4.68V），不能接 3.3V**
      （LVC 的 V_OH ≈ VCC-0.1，4.68V 时 ≈4.6V > 0.7×4.68V = 3.28V 才满足灯带的 V_IH；
      输入侧 V_IH 只要 2.0V，3.3V 的 PB6 完全够用）。VCC 就近再并一只 100nF。
      ⚠ **SN74LVC1G126 与 1G125 脚位完全一样，但 OE 是高有效**：若错用 126 且把 OE 接 GND，
      输出进高阻 → 灯带全黑，务必核对型号/丝印；
   ② 灯带 VCC 串一只 1N4148 降到 ~4.3V（仍在灯珠工作范围内）；
   ③ 数据线缩短到 10cm 以内（走线电容小，3.3V 也可能被识别，但不保证）。
2. **灯带没供电 / 没共地**：量灯带 VCC ≈ 5V；**MCU 的 GND 必须和灯带的 GND 直接连在一起**
   （各自通过 USB 接地是错的：数据线没有共同参考电平 → 全黑）。
3. **DIN/DOUT 接反**：数据从 MCU 进 **DIN**，灯带上有箭头，只能顺着箭头方向传；接在 DOUT 或灯带末端上永远不亮。
4. **灯珠型号不是普通 WS2812B**：SK6812 **RGBW** 是 32 位/颗（本驱动按 24 位发 → 整体错位）；
   12V 灯带（WS2815 等）不是 800kHz 单线时序；APA102/SK9822 是 CLK+DATA 双线 SPI → **本驱动完全不适用**。
5. **PB6 到灯带之间还有一级反相/缓冲电路**：有些板子为了驱动能力加了三极管/缓冲器，可能把数据**反相** → 全黑。
   直接量灯带 **DIN** 焊盘：正确波形是"位周期 = `WS2812_BIT_NS`、高电平 = `WS2812_T0H_NS`（0 码）/
   `WS2812_T1H_NS`（1 码）的向上正脉冲"，不是它的反相。

**第 4 步：用按键灯（PC4，4 颗）做交叉验证。** 按键灯和主灯带是完全独立的两条通路（一条软件位打、一条 PWM+DMA）：
* 按键灯会亮、主灯带不亮 → 5V 与共地在，问题就锁定在主灯带这一路（PB6 波形 / 电平 / DIN / 型号）；
* 两条都不亮 → 先查 **5V 供电与共地**（可用 `KEYLED ALL 255 0 0` 整排点亮按键灯对比）。

> 说明：本驱动是"CCR 预装载 + DMA 在比较匹配时写 CCR"的经典方案，上电**第一帧会多 1 个 0 位**，
> 之后所有帧完全正确（见 3.2 节末尾），这不会导致全黑，排查时可以忽略。

### 3.3 按键灯（`drv_keyled`）—— 不用 PWM
* 每位 = **高电平 + 低电平**两段，0 码和 1 码各自独立取值：规格书只规定这四段各自的
  上下限，并没有“位周期必须 1.25µs”这条硬约束，所以驱动**不设位周期** ——
  位周期就是 `T?H + T?L`（两段之和）自然形成的。默认值同时落在 WS2812B 与
  WS2812B-V5 两份规格书的**交集**里，并且取在交集**偏下侧**：自标定用的是“取最小值”，
  只会“欠补”不会“过补”，所以灯珠实际看到的相位只会比目标**偏长 0~5 拍、不会偏短**；
  目标压在下沿，往上偏长以后依然在窗口内。
  默认取值见 `bsp_config.h` 第 5 节（那里逐条写了为什么这么取），这里只列**手册窗口**：

  | 宏 | 相位 | WS2812B | WS2812B-V5 |
  |---|---|---|---|
  | `KEYLED_T0H_NS` | 0 码高电平 | 250~550 | 220~380 |
  | `KEYLED_T0L_NS` | 0 码低电平 | 700~1000 | 580~1000 |
  | `KEYLED_T1H_NS` | 1 码高电平 | 650~950 | 580~1600 |
  | `KEYLED_T1L_NS` | 1 码低电平 | 300~600 | 220~420 |

  两份手册的交集是 `T0H 250~380 / T0L 700~1000 / T1H 650~950 / T1L 300~420`，
  交集外无论怎么调都必然违反其中一份手册 —— `T1L` 尤其窄（上限 420ns），
  换灯珠型号后第一件事就是验这四段。
  按“标定只欠补、实际相位只会偏长 0~5 拍”的性质，默认值把四段取在交集下沿即可 ——
  最坏情况下四段仍落在两份窗口内（推演过程留在 `bsp_config.h` 第 5 节，本文档不重复）。

* **上电自标定**：`keyled_init()` 先把 PC4 设成“输入 + 下拉”（不驱动灯带），用 DWT 实测
  这四段“实际有多长”（取最小值，避开中断干扰），把延时函数/循环的固定开销扣掉以后再发第一帧
  —— 所以 `KEYLED_T0H_NS / T0L_NS / T1H_NS / T1L_NS` 填的就是灯珠真正看到的时间，
  不用再手工猜 `KEYLED_CYC_COMP`（只有 DWT 不可用时才退回固定补偿）。
* **发第一帧之前先给一段复位电平**（长 = `KEYLED_RESET_US`，规格书要求 ≥280µs），并在
  `keyled_init()` 结尾**连发 `KEYLED_INIT_FRAMES` 帧全零**。原因：上电瞬间引脚是浮空的，
  灯珠可能已经把噪声锁存成自己的“上电默认色”（有的批次上电就是全白）；只补一帧，
  万一这一帧被破坏就会一直停在白色。多帧全零保证上电一定落到“全灭”。
  （切换输出模式前驱动还会先把 ODR 写成空闲电平，免得从输入态切过来的瞬间冒一个高脉冲。）
  串口 `KEYLED DIAG` 能看到实测周期数、扣掉的开销、数据线极性、每一路的设定色 / 输出色，
  外加一行数据线自检 `line low=/high=`（驱动低/高时引脚读回的电平，正常应与驱动一致）。
* 位与位之间：先拉高、再拉低，两段各自计时；两段的**时间基准都取在管脚刚翻转之后**
  （写完 GPIO 寄存器立刻采样），所以写寄存器那十来拍既不算进高电平也不算进低电平
  （旧版把基准取在写寄存器**之前**、又用“固定 1.25µs 位周期”去撑低电平：灯珠看到的
  高电平比配置值短约 200ns，`T1L` 被压到 30 多拍（约 600~700ns）、`T0L` 被撑到 1.1µs，
  四条相位里两条低电平都跑出手册 —— 这就是“三颗一起发白”的根因）。
* 一次输出 = `KEYLED_NUM` × 24 位，时长 = 位数 × 位周期（0 码 ≈ `KEYLED_T0H_NS`+`KEYLED_T0L_NS`、
  1 码 ≈ `KEYLED_T1H_NS`+`KEYLED_T1L_NS`），期间关中断（可用 `KEYLED_LOCK_IRQ` 关闭）。
* 支持 `KEYLED_FX_OFF/STATIC/BLINK/BREATHE`，`keyled_process()` 内部限速刷新（周期见 `drv_keyled.c`）。
* **三颗（或四颗）灯一起发白 / 颜色不对** = 要么帧**根本没被灯珠锁存**（灯恒白、任何命令都不理），
  要么位时序被灯珠误判了（一片白 = 整帧被读成“1”）；两者处理方式完全不同，先按下面表定性。
  串口可以实时扫，不用重编译（改完立即重发一帧，现场马上能看到）；**允许范围与默认值只在
  `bsp_config.h` 第 5 节和 `drv_keyled.c` 的 `KEYLED_T*_MIN/MAX_NS` 定义**，超范围会被自动夹回来。

  **先分清四种“全白 / 点不灭”**（30 秒能定性：`KEYLED ALL 0 0 0` 与 `KEYLED ALL 255 255 255` 各发一次，
  看灯怎么变；主灯带的故障定位思路同样适用）：

  | 现场现象 | 结论 | 下一步 |
  |---|---|---|
  | 发 `ALL 0 0 0` **毫无反应**（灯恒白，任何颜色命令都不理） | 帧根本没被**锁存**：DIN 上没出现 ≥280µs 的复位低电平 → 灯珠一直停在自己的**上电默认色**（部分批次上电就是全白） | ① `KEYLED INVERT 1`（线上有反相器 / 三极管时，连空闲电平都得一起反）；② 量 DIN 空闲电平（不发数据时必须是**低**）；③ 量 DIN 高电平幅值是否 ≥ 0.7×VDD（3.3V 直驱 5V 灯珠就是主灯带那个坑，要加电平转换） |
  | `ALL 0 0 0` → **全白**，`ALL 255 255 255` → **全灭**（黑白颠倒） | 整条波形被取反：0 码被当成 1 码 | 硬件反相 → `KEYLED INVERT 1`；否则按下面第 1、2 条扫 `T0H / T1H` |
  | 发什么都**偏白偏亮**，但能看出深浅差别 | 0 码高电平偏长（被读成 1 码） | 往下扫 `KEYLED T0H`；同时看 `KEYLED DIAG` 的实测周期数是不是远大于配置值（`calib=` 为 0 = 自标定没生效） |
  | `KEYLED DIAG` 的 `line low=/high=` 与驱动电平不一致 | 数据线被外部强驱动 / 接错线 / 和别的信号短接 | 查接线，别改代码 |

  扫法就是"以当前值为中心、两个方向各挪一档"（一档 ~50ns；当前值用 `KEYLED DIAG` 看）：
  1. 挪 `KEYLED T0H <ns>`：0 码高电平**偏长**最容易被读成“1”（→ 偏白）；
     默认值贴着交集下沿，往长调是危险方向，往短调更安全；
  2. 挪 `KEYLED T1H <ns>`：1 码高电平偏短会被读成“0”（→ 变暗 / 不亮），
     同时注意 `T1H - T0H` 至少要差 `KEYLED_T1H_GAP_NS`，否则灯珠分不开两个码；
  3. 挪 `KEYLED T0L <ns>` / `KEYLED T1L <ns>`：低电平跑出范围同样会整帧错位
     （交集里 `T1L` 的上限最紧，往长调最容易踩线）；
  4. `KEYLED INVERT 1`：数据线上若串了反相器 / 三极管，整条波形要取反（含空闲电平）；
  5. `KEYLED DIAG`：把打印出来的值发回来定位。
  找到好用的组合后，把值写回 `bsp_config.h` 的
  `KEYLED_T0H_NS / T0L_NS / T1H_NS / T1L_NS / KEYLED_INVERT`。
  游戏里还额外用 `WSGAME_KEYLED_LEVEL` 把三色打折（取值见 `bsp_config.h` 第 10 节），免得又刺眼又被看成白。
* 现场先单颗试色：`KEYLED 0 255 0 0`（第 1 颗红）、`KEYLED 0 0 0 255`（第 1 颗蓝）、
  `KEYLED ALL 0 255 0`（四颗绿），命令见第 4 节 —— 别只盯游戏画面判断。

### 3.4 数码管（`drv_hc595`）
* 段码位：bit0~bit6 = a~g，bit7 = dp；`HC595_ACTIVE_LEVEL` 选择共阴/共阳（共阳自动取反）。
* `hc595_show_int(1234)`、`hc595_show_digits("A1-2")`、`hc595_set_dp_mask()`、`hc595_clear()`。
* 位序与焊接顺序不一致时用 `HC595_DIGIT_REVERSE` 切换（`bsp_config.h` 第 6 节）：
  **本板实测是反的**（第 1 位会显示到第 4 位上），所以默认 `HC595_DIGIT_REVERSE = 1`
  （即 `hc595_digit_map[] = {3,2,1,0}`）；换板子若发现又反了，改回 `0U` 即可。

#### 74HC595 级联接线速查（DIP16）

| 595 引脚 | 名称 | 接到哪里 |
|---|---|---|
| **14** | DS / SER | MCU 的 SDI（本工程 **PC6**）——**数据入口，接错这里就永远不显示** |
| 11 | SHCP / SRCLK | MCU 的 SCLK（**PC7**），上升沿把数据移入 |
| 12 | STCP / RCLK | MCU 的 LOAD（**PC8**），上升沿把移位寄存器送到输出锁存器 |
| 13 | OE̅ | **必须接 GND**（悬空/接高 → 输出高阻 → 全黑） |
| 10 | MR̅ | **必须接 VCC**（拉低 → 移位寄存器清零 → 一直不亮） |
| 9 | QH′ | 级联到**下一片的 14 脚**（这是输出，不是给 MCU 用的输入！） |
| 16 / 8 | VCC / GND | 5V / GND，每片旁边 0.1µF 去耦 |

> 本项目的实际故障就出在这里：PC6 接到了 595 的 **9 脚（QH′，级联输出）** 而不是 **14 脚（DS，数据入口）**，
> 数据永远进不了移位寄存器，输出锁存器一直停留在上电的全 0 → 共阳屏表现为**全段 + 小数点常亮**（见下表）。

#### 上电 3 步自检（`HC595_BOOT_SELFTEST`，默认 **0** = 关闭）

需要排查数码管时把它置 **1** 重新编译：上电后数码管按顺序走 `8888` → 全灭 → `1234`
（每步显示 `HC595_SELFTEST_MS`），按下面这张表对号入座，一次就能定位问题；
排完改回 0（正常固件不需要这几百毫秒的延时）。

| 现象 | 原因 | 处理 |
|---|---|---|
| **全部段连小数点一起常亮** | 板子是**共阳**，但 `HC595_ACTIVE_LEVEL` 写成了 `1U`（共阴）：清屏/空格的段码是 `0x00`，不取反直接输出 → 595 八个输出全低 → 共阳管全部点亮 | 把 `HC595_ACTIVE_LEVEL` 改成 **`0U`**（本工程默认已是 `0U`） |
| 改好极性后**依然全亮、任何时刻都不变** | 数据根本没移位进 595：PC6 接到了 9 脚（QH′）而不是 14 脚（DS），或 595 的 `OE` 被拉高、`MR` 被拉低、`VCC/GND` 没接好 | 按上面的接线速查表逐脚核对；再用示波器/逻辑笔量 PC6/PC7/PC8 有没有跳变 |
| 显示**满是"Ｌ"或 g 段**（每一步都只有 g+小数点亮） | 段码送反 + 位序对不上（典型是共阴表配共阳屏的中间态） | 先确认共阴/共阳，再调 `hc595_digit_map[]` |
| `8888` 正常，`1234` 显示的**数字顺序左右颠倒** | 级联方向与预期相反（先移入的字节落在最近的 595 上） | 把 `hc595_digit_map[]` 改成 `{3U, 2U, 1U, 0U}` |
| `8888` 时**小数点也亮** | 段码表里 `dp` 不是 bit7，或硬件 dp 接在别的 Q 上 | 对照原理图改 `hc595_char_to_seg()` 里的 bit7 与硬件 Q 的对应关系 |
| 某一段**永远不亮**（例如 a 段） | 该段 LED / 限流电阻 / 595 对应输出脚虚焊 | 硬件检查，与软件无关 |

> 74HC595 上电时输出寄存器是 **全 0**，所以共阳屏在"程序还没写数据"或"数据没送进去"时，
> 表现都是**全亮**——这就是上电瞬间看到全亮（含小数点）的原因。

### 3.5 ESP32-C3 串口（`drv_esp32`）
* USART1 中断收 → 512B 环形缓冲 → `esp32_process()` 按行拆包 → 回调 `esp32_set_rx_handler()`。
* 发送：`esp32_send/send_str/send_line/printf`（带 TXE 超时保护，不会死等）。
* 统计接口：`esp32_rx_total/rx_lines/rx_overflows/rx_errors`（判断链路是否丢数据）。


### 3.6 语音模块 WT2003H4-16S（`drv_wt2003h`）—— Key 口与串口合并成一个方法
业务层只需要记一个入口：

```c
wt2003_talk(voice_id);        /* 自动选路: 查绑定表 → 命中走 Key 口(最快), 否则走串口 */
```

* 绑定关系：`wt2003_bind_key(voice_id, key_idx)`（0/1/2 → K1/K2/K3，`0xFF` 解除）。
  **默认关闭 Key 口**（`WT2003_KEY_ENABLE = 0`）：本项目的标准品 WT2003H4-16S 未开放
  Key 口功能（需芯片厂家定制），所以上电不再建立"1/2/3 → K1/K2/K3"绑定，
  `wt2003_talk()` 一律走串口 `A0`，不会出现"编号 1/2/3 静默无反应"；
  `VKEY` 也会直接回 `ERR VKEY unavailable`。改用定制模块时把该宏置 1 即可恢复原行为
  （宏位 1 时上电默认：编号 1/2/3 分别走 K1/K2/K3）。
* 想强制某条通路：`wt2003_talk_src(id, WT2003_SRC_UART)` 或 `WT2003_SRC_KEY`
  （Key 口关闭时 `SRC_KEY` 会自动退回 `SRC_UART`，保证"要播就能播"）。
* **串口协议（已对齐《WT2003HX 芯片》手册）**：

  帧格式：`7E | 长度 | 命令 | 数据… | 校验码 | EF`
  * 长度 = `1(长度字节自身) + 1(命令) + N(数据) + 1(校验码)`（**含自己**）；
  * 校验码 = 从"长度"字节起逐字节累加和（mod 256）。

  例（手册原例，本驱动发出的帧与之一致）：
  ```
  A0 SPI Flash 索引 1 :  7E 05 A0 00 01 A6 EF   (05+A0+00+01 = A6)
  A6 U 盘 索引 2      :  7E 05 A6 00 02 AD EF   (05+A6+00+02 = AD)
  AE 音量 = 31        :  7E 04 AE 1F D1 EF      (04+AE+1F     = D1)
  ```

  > ⚠ **介质决定命令码**：`A0` 只播 **SPI Flash** 上的文件，`A6` 只播 **U 盘**上的文件（手册 4.1.3.4）。
  > 命令用错时模块会回**非 0**（"指定曲目不存在"）而**不出声** —— 实测现象就是"命令回了、索引也在、就是没声音"。
  > 本项目音频放在 **U 盘**上，所以走 `A6`（`bsp_config.h` 的 `WT2003_PLAY_USE_UDISK = 1`）。

  命令码（`drv_wt2003h.h` 的 `WT2003_CMD_*`）：

  | 码 | 功能 | 数据 | 封装函数 |
  |---|---|---|---|
  | `A0` | 指定 **SPI Flash** 根目录索引播放 | 曲目号 2 字节(高/低) | `wt2003_play_flash(id)` |
  | `A1` | 指定 **Flash** 按文件名播放 | 文件名 4 字节 ASCII | —（手册 4.1.3.3） |
  | `A6` | 指定 **U 盘**根目录索引播放 | 曲目号 2 字节(高/低) | `wt2003_play_udisk(id)` |
  | `A7` | 指定 **U 盘**按文件名播放 | 文件名 4 字节 ASCII | `wt2003_play_udisk_name("T002")` |
  | `A8` | 指定 **U 盘文件夹内**文件索引播放 | 文件夹名 5 字节 + 索引 2 字节 | `wt2003_play_udisk_folder("MUSIC", n)` |
  | `AA` | 播放暂停（播放 <-> 暂停 切换） | 无 | `wt2003_pause()` |
  | `AB` | 停止 | 无 | `wt2003_stop()` |
  | `AC` | 下一曲（跟当前工作盘符） | 无 | `wt2003_play_next()` |
  | `AD` | 上一曲（跟当前工作盘符） | 无 | `wt2003_play_prev()` |
  | `AE` | 音量控制 | 0~31 | `wt2003_set_volume(v)` |
  | `AF` | 指定播放模式 | `00` 单曲不循环 / `01` 单曲循环 / `02` 全部循环 / `03` 随机 | `wt2003_set_mode(m)` |
  | `B1` | 插播 | 标示字（`00`=Flash / `02`=U 盘）+ 索引 2 字节 | `wt2003_insert(buf, len)` |
  | `B6` | 音频输出方式 | `00`=SPK / `01`=DAC（手册示例：**无返回码**） | `wt2003_set_output(...)` |
  | `B7` | Flash 引脚加载 / 释放 | `00`=释放 / `01`=加载 | `wt2003_flash_pin(load)` |
  | `D2` | 切换当前工作盘符 | `00`=SPI-Flash / `02`=U 盘 | `wt2003_select_drive(WT2003_DRIVE_UDISK)` |
  | `C0` | 查询软件版本（手册未列出，实测有应答） | — | `wt2003_query_version()` |
  | `C1` | 查询当前设置音量 | — | `wt2003_query_volume()` |
  | `C2` | 读取当前工作状态（`01` 播放 / `02` 停止 / `03` 暂停） | — | `wt2003_query_status()` |
  | `C3` | 查询 **SPI-Flash** 内音乐文件总数 | — | `wt2003_query_file_num()` |
  | `C7` | 查询 **U 盘**内音乐文件总数 ← **本项目用这条** | — | `wt2003_query_udisk_num()` |
  | `C8` | 查询 U 盘指定文件夹内文件总数（回 `00 00` = 无此文件夹） | 文件夹名 5 字节 | `wt2003_query_ufolder_num("MUSIC")` |
  | `C9` | 查询当前播放文件曲目 | — | `wt2003_query_cur_file()` |
  | `CA` | 查询当前外设连接状态（bit3=PC / bit2=U 盘 / bit0=SPI-Flash，1=存在） | — | `wt2003_query_conn()` |
  | `CB` | 查询当前播放歌曲名（8 字节 ASCII，不足补 `20`） | — | `wt2003_query_cur_name()` |
  | `B0` / `B8` | 组合播放 / 低功耗（本版手册未列出，保留兼容） | — | `wt2003_play_combo` / `wt2003_low_power` |

  > **介质千万别搞错**：`A0/A1` 与 `C3` 是 **SPI-Flash**；`A6/A7/A8` 与 `C7/C8` 是 **U 盘**。
  > 本项目音频在 U 盘 → 播放用 `A6`（或 `A7/A8`），"还有几个文件"看 `C7`，
  > "模块认到盘没有"看 `CA` 的 bit2；`C3` 恒为 0 属正常（它查的是 SPI-Flash）。

  > **写命令的返回码**（手册 4.1.3.1"写操作指令返回码格式"）：执行完每条写命令，模块回
  > `<命令码> <1 字节操作码>`：`00 = OK` / `01 = FAIL（出错，不执行）` / `02 = EMP（无此文件）`。
  > ★ 但本模块（`WT2003H4-16S`，固件 `WTS251016-70-A01V4.01`）实测 `D2` / `A6` / `C7`
  > 都回 **`0x05`** —— 手册里没有这个值，而同一轮音频**照样播出来了**：
  > 所以 **`0x05` 绝不能当"没播"**，`A6`/`D2` 回非 0 不等于失败，`README 8.7` 有完整判读。
  > 查询命令（`C1/C2/C3/C7/C8/C9/CA/CB`）回的是**数据**、不是返回码，别套这张表。

  > 音量共 **32 级（0~31）**：0 = 静音、31 = 最大；此命令**掉电记忆**，模块上电默认最大（`1F`）。
  > 查询命令只发帧，应答由 `wt2003_set_frame_handler()` 回调上报（远程命令 `VQRY` 可触发，见第 4 节）。
  > **按索引播放**的封装函数 `wt2003_play_index(id)` = `wt2003_talk()` 走串口那条路，它用哪条命令
  > （`A6` 播 U 盘 / `A0` 播 SPI Flash）由 `bsp_config.h` 的 `WT2003_PLAY_USE_UDISK` 选（默认 `1` = `A6`）。
  > **⚠ 但本模块实测 `A6` 收下命令却不出声（第五轮定论，见 8.9）**：要播指定语音请改走
  > `A7` 按文件名播放 —— `wt2003_play_udisk_name("T001")` / 远程 `VNAME <n>`（文件名 4 字符、放 U 盘根目录）。

* **按文件名轮播（`WT2003_NAME_CYCLE_ON_BOOT`，当前为 **1** = 开）**：上电用 `A7` 每
  `WT2003_NAME_CYCLE_MS`（`4000` ms = **4 秒**）播 `WT2003_NAME_CYCLE_LIST` 里的下一个文件名并循环，
  播后自动查一次 `C9`/`CB`（确认模块到底播的是哪一首）；数码管显示第几个，串口打 `NAME n/N "T00n"`。
  **这是本模块唯一能播指定语音的路**（`A6` 无效，见 8.9）；不用时置回 `0`。
  远程命令：`VNAME`（列名字表）/ `VNAME <n>`（立刻播第 n 个）/ `VNAMEON` / `VNAMEOFF`。
* **语音链路自检序列（`WT2003_PROBE_ON_BOOT`，当前为 **0** = 关闭 —— 第五轮结论已拿到（见 8.9），
  正式模式走"按文件名轮播"或开机提示音 `WT2003_BOOT_VOICE`；要复现时再置 1）**：置 1 时上电后按
  各步自己的间隔自动走完 **38 步**，**数码管显示第几步**（`0001`~`0038`），
  同时从 ESP32 串口打一行 `PROBE n/38 <说明> rx=..`；结束时数码管显示模块**回帧计数**低 4 位
  （`0000` = 模块一句都没回），串口还会打一行 `PROBE DONE rx=.. cmd=..`。
  也可随时用远程命令 `WTPROBE n` 单独发第 n 步、`WTSTOP` 停止、`WTST` 看状态。
  排查完把 `WT2003_PROBE_ON_BOOT` 改回 **0**（仓库默认就是 0；正式模式只播开机提示音）。

  > 索引 1~4 回 `02`、`C0 = WTS251016-70-A01V4.01`，全程无声。

  > → "忙"和"没文件"都被排除，嫌疑落在「模块播不了这些文件（格式 / 文件系统）」或「曲目索引没建立」，
  > 靠第 15 / 17 步（`AA` / `AC`，绕过索引）来区分。
  > Key 口：本项目标准品 WT2003H4-16S 没开放 Key 口功能（需厂家定制，`WT2003_KEY_ENABLE = 0`），
  > 自检序列里的 Key 步骤已移除（`VKEY` 会直接回 `ERR VKEY unavailable`）；换成定制模块后
  > 用 `VKEY 0/1/2` 单独触发即可。
  > 索引：`A0`/`A6` 的曲目号是 2 字节（高/低），模块内文件索引通常按扫描顺序，不一定等于文件名数字。
  > 介质：本项目用 **U 盘**（`A6`，`WT2003_PLAY_USE_UDISK = 1`）；用错命令（拿 `A0` 播 U 盘）会回非 0 且不出声。
* Key 口：开漏输出 + 低脉冲（脉宽 = `WT2003_KEY_PULSE_MS`，由 `wt2003_process()` 到点释放，**不阻塞业务**）。
* 其他串口命令：`wt2003_play_index / play_next / play_prev / pause / stop / set_volume /
  set_mode / play_combo / insert / set_output / low_power / query_*`，
  也可用 `wt2003_send_cmd(cmd, data, len)` 或 `wt2003_send_raw(frame, len)` 发手册上的任意帧。
* 模块返回帧由 `wt2003_process()` 解析，结果通过 `wt2003_set_frame_handler()` 回调上报
  （驱动已剥掉命令码与校验码，回调拿到的是纯数据区）。

**⚠ 与实物核对清单（都集中在 `bsp_config.h` / `drv_wt2003h.h`）：**

1. **命令码**：`WT2003_CMD_*`（已按 WT2003HX 手册填好：`A0/A6/AA/AB/AC/AD/AE/…`）；固件不同时只改这一处。
   **按索引播放用哪条命令**由 `bsp_config.h` 的 `WT2003_PLAY_USE_UDISK` 决定（**U 盘 = `A6`**：置 `1`；SPI Flash = `A0`：置 `0`）。
2. **帧格式**：`WT2003_USE_CHECKSUM = 1`、`WT2003_LEN_COUNT_SELF = 1`（手册固定如此，勿改）。
3. **波特率**：`WT2003_BAUD`（取值见 `bsp_config.h` 第 8 节）。
4. **音频输出方式**：喇叭接模块内部功放（SPK）却无声时，用 `VOUT 0` 或上电发一次 `B6 00` 切回 SPK。

### 3.7 一键开关机（`drv_power`）
* `power_init()`：**先开 GPIOC 时钟 → 立即把 PC3 拉成"保持供电"电平 → 再配置为推挽输出**（顺序很关键，否则松手断电）。
* PA7 电源键：内部上拉 + EXTI7 下降沿（中断只记时间戳），主循环按 `POWER_KEY_POLL_MS` 轮询消抖：
  * 长按到 `POWER_OFF_LONG_MS` → `power_request_shutdown()`：先调用关机回调（播提示音/关灯/存参数），
    延时 `POWER_SHUTDOWN_NOTICE_MS` 后拉掉 PC3 断电；
  * 长按到 `POWER_FORCE_OFF_MS` → 立即断电（强力兜底）；
  * 短按 → 短按回调（业务层自定义，例：上报 WiFi）。
* 调试时 USB 供电不会真的掉电，程序会停在 `__WFI()` 死循环里（`POWER_HARD_CUT_LOOP=1`）；不想这样就把该宏改成 0。

### 3.8 时间基准（`bsp_time`）
* 延时：DWT->CYCCNT 周期计数，72MHz 下 13.9ns 分辨率（WS2812 软件时序靠它）。
* 时间戳：TIM2 是 16 位，因此配置成 **1ms 中断**（PSC=71、ARR=999），中断里累加软件计数器：
  * `bsp_time_ms()` 32 位毫秒（49.7 天回绕）
  * `bsp_time_us()` 微秒（读"毫秒累加值 + 当前 1µs 计数"，带重读保护）
* 判断时间差一律用 `bsp_elapsed_ms()/bsp_elapsed_us()`（无符号差值，跨回绕安全）。
* 若你的板子不方便用 TIM2，可以把 `bsp_time.c` 里的 `BSP_TIME_TIM` 换成 TIM3/TIM5（注意别和灯带的 TIM4 冲突）。

### 3.8 RTOS 任务划分与资源保护（`app_task` + `bsp_rtos`）

> 只想跑裸机？把 `Inc/bsp_config.h` 里的 `BSP_USE_RTOS` 改成 0 即可：`app_task_start()`
> 会立刻返回，由 `main.c` 末尾的主循环轮询所有 `*_process()`，功能完全一样（便于对比/移植）。

四个任务（周期、优先级都在 `bsp_config.h` 第 9 节）：

| 任务 | 周期 | 优先级 | 干什么 |
|---|---|---|---|
| `input` | 5ms | AboveNormal | `drv_key_process()` 消抖 + 短按/长按、`power_process()` 电源键 |
| `light` | 10ms | Normal | `led_fx_process()` 灯带动画、`keyled_process()` 按键灯 |
| `comm` | 100ms（有数据立刻唤醒） | Normal | `esp32_wait_data()` → `esp32_process()` → `app_cmd_process()` |
| `voice` | 10ms（有请求立刻唤醒） | BelowNormal | `wt2003_take_request()` → `wt2003_exec_request()` → `wt2003_process()` |

三条"不会被 RTOS 破坏"的设计原则：

1. **精确时序不交给任务**：WS2812 的 PWM+DMA、按键灯位打（一帧全程关中断，时长随 `KEYLED` 位时序）、74HC595 移位、
   `bsp_delay_us()` 仍然在中断里或短临界区里完成，任务只负责算颜色、填缓冲。
2. **时间判断仍然用 TIM2**：`bsp_time_ms()` / `bsp_elapsed_ms()` 来自 TIM2 中断，与 RTX 的
   SysTick 相互独立，跨任务跨中断都安全；所以任务周期抖动不影响按键/动画的正确性。
   `bsp_sleep_ms()` 只是"让出 CPU"，不要把它当成精确延时。
3. **共享资源一把锁**：串口发送（`drv_esp32`）、灯带颜色缓冲（`drv_ws2812`，配合
   `ws2812_lock()/ws2812_unlock()` 包住"改多颗 + show"）、按键灯缓冲（`drv_keyled`）各自用
   `bsp_mutex_t` 保护；"中断 → 任务"的通知用 `bsp_signal_t`（`esp32_wait_data()`、
   `drv_key_wait_event()`）或 `bsp_queue_t`（WT2003 播放请求），不再用全局标志忙等。

必须在 `RTE\CMSIS\RTX_Conf_CM.c` 里核对的三项：

* `OS_CLOCK` = **72000000**（必须等于 `BSP_SYSCLK_HZ`，否则 `osDelay` 的超时会成比例偏差）；
* `OS_STKSIZE` = 256（单位: 字, 即 1KB/任务）、`OS_MAINSTKSIZE` = 256；
* `OS_TASKCNT` = 8（本工程用 4 个用户任务 + 定时器任务，留有余量）。

### 3.9 灯带消消乐（`app_wsgame`）—— 游戏层

> 玩法：灯带是一条**运输带**。随机 **蓝 / 绿 / 紫** 的单颗灯从**远端**冒出来，整条缓慢往
> **近端**挪；每 `WSGAME_SPAWN_MS` 在远端再补一颗 —— 前一颗没消掉，后面就紧跟着再来一颗，
> 场上的灯越积越多，一起往近端挤。
> 近端按 **Key1/Key2/Key3** = 朝远端**发射**一颗同色子弹（比灯快得多）；
> 子弹撞上**同色**灯 → 两颗一起消失（白闪 + 得分）；
> 撞上**不同色** → 子弹**自己也消失**（色块留在原地、不得分，也不会挡住后面的子弹）；
> 一直没被消掉的灯走到近端 = **漏掉**（只计数不扣分，近端灰白微亮一下提示），然后消失。

**远 / 近端与方向**

| 名称 | 索引 | 说明 |
|---|---|---|
| 近端 | 0 | 数据入口（DIN）这一端：按键在这头，灯冲着你来，**子弹从这里发出** |
| 远端 | `WS2812_LED_NUM`−1 | 灯带末端：**灯从这里冒出来**，子弹飞到这儿就收回 |

* 节奏：运输带每 `WSGAME_TRACK_STEP_MS` 整体挪一颗灯（走完全程 = 该值 × 灯数）；远端口子每
  `WSGAME_SPAWN_MS` 补一颗，所以相邻两颗的间距 = `WSGAME_SPAWN_MS` ÷ `WSGAME_TRACK_STEP_MS` 颗灯，
  场上同时有十几二十颗。默认值见 `bsp_config.h` 第 10 节。
* 子弹每 `WSGAME_SHOT_STEP_MS` 飞一颗灯（飞到远端 = 该值 × 灯数），最多同时 `WSGAME_MAX_SHOTS` 颗；
  连点按键可以连发。
* **装机方向反了**（看着像往外跑）不用改接线：把 `bsp_config.h` 的 `WSGAME_REVERSE_DIR` 改成
  `1U` 即可 —— 只镜像渲染索引，逻辑完全不变。

**按键 / 按键灯映射**

| 按键 | 引脚 | 发射颜色 | 按键灯（PC4 的 4 颗） |
|---|---|---|---|
| Key1 | PA0 | 蓝 | 第 1 颗：常亮蓝（发射时闪一下） |
| Key2 | PA1 | 绿 | 第 2 颗：常亮绿（发射时闪一下） |
| Key3 | PA2 | 紫 | 第 3 颗：常亮紫（发射时闪一下） |
| Key4 | PA3 | — | 第 4 颗：运行指示（亮 = 运行中） |

* **Key4 短按 = 开始 / 暂停**，不用串口也能开局（也可以在 `app_wsgame.h` 里把
  `WSGAME_KEY_BLUE/GREEN/PURPLE/START` 改成别的键）。
* 颜色键只认 `KEY_EV_DOWN`（按下立刻发一颗），松手 / 长按保持都不会补发。
* 按键亮度和三色值在同一处：`WSGAME_KEYLED_LEVEL`（取值见 `bsp_config.h` 第 10 节，怕刺眼 / 怕被看成一片白就调小）、
  `WSGAME_BLUE_* / GREEN_* / PURPLE_*`（色块、子弹、按键灯共用）。
* 游戏停止后 4 颗按键灯全灭，交还 `app_cmd` 的"按下点亮"反馈（`app_key_callback()` 里用
  `wsgame_is_running()` 让位）。
* 若按键灯的物理顺序与 Key1~Key3 不一致（例如第 1 颗灯焊在 Key2 下面），改
  `app_wsgame.c` 里 `keyled_apply()` 的索引即可（`app_cmd` 的按下反馈本来就是"按键号 = 灯号"）。

**碰撞与判定**

```
    近端(0)                                                远端(灯数-1)
      │  每 SPAWN 在远端补一颗, 前一颗没消掉就紧跟其后          │
      │   ◄── 整条每 TRACK 往近端挪一格 ◄──                     │  ●绿 ●紫 ●蓝 ●绿 ●紫 …
  按 Key2 ─►  ●绿 ──►(每 SHOT 飞一颗)──► 撞上 ●绿 → 两颗一起消失(白闪+1分)
                                          撞上 ●蓝/紫 → 子弹消失, 色块留在原地
      ● 走到 0 还没被消掉 → 漏掉(计数, 近端灰白微亮一下)后消失
```

> 图里 `SPAWN / TRACK / SHOT` = `WSGAME_SPAWN_MS` / `WSGAME_TRACK_STEP_MS` / `WSGAME_SHOT_STEP_MS`，
> `白闪 / 微亮` 的时长 = `WSGAME_HIT_MS` / `WSGAME_MISS_MS`（数字都在 `bsp_config.h` 第 10 节）。

* 判定在**每一格**都做：子弹飞到某格、或灯挪到子弹所在格，都算撞上。
* **同色必消**（一发子弹只消一颗）；**异色同归于“子弹”**：撞上不同色的灯，子弹自己消失，
  色块原地不动、不得分，也不会挡住后面飞来的同色子弹（串口 `WSGAME TRACE` 会打一行 `BLOCK`）。
* 一发子弹从索引 0 出发，`pos >= WS2812_LED_NUM`（越过末位）就收回；近端最外那颗（索引 0）上也照样能打 ——
  按下按键的瞬间就判一次，救得回来。

**参数**（全部集中在 `bsp_config.h` 第 10 节，改完重新编译即可）

| 宏 | 作用 |
|---|---|
| `WSGAME_AUTOSTART` | 1 = 上电直接开局；0 = 上电跑 `COMET`，用 Key4 / `GAME START` 开局 |
| `WSGAME_TRACK_STEP_MS` | 运输带速度：每挪一颗灯的毫秒数（**越大越慢**；可调范围 `WSGAME_TRACK_STEP_MIN`~`MAX`） |
| `WSGAME_SPAWN_MS` | 远端口子：每多少毫秒冒一颗新灯（范围 `WSGAME_SPAWN_MIN`~`MAX`） |
| `WSGAME_SHOT_STEP_MS` | 子弹速度：每飞一颗灯的毫秒数（**越小越快**；范围 `WSGAME_SHOT_STEP_MIN`~`MAX`） |
| `WSGAME_MAX_SHOTS` | 同时最多几颗子弹（连点上限） |
| `WSGAME_HIT_MS` / `WSGAME_MISS_MS` | 命中白闪 / 漏掉时近端提示的时长 |
| `WSGAME_KEYLED_FLASH_MS` / `WSGAME_KEYLED_BLINK_MS` | 发射时按键灯闪烁时长 / 闪烁周期 |
| `WSGAME_FRAME_MS` | 画面刷新周期 |
| `WSGAME_BLUE_*` `WSGAME_GREEN_*` `WSGAME_PURPLE_*` | 三色 RGB（灯、子弹、按键灯共用同一组值） |
| `WSGAME_KEYLED_LEVEL` | 按键灯三色的亮度折扣 |
| `WSGAME_AVOID_REPEAT` | 1 = 相邻两颗不同色 |
| `WSGAME_SEG_SCORE` | 用 4 位数码管显示得分（命中 +1） |
| `WSGAME_TRACE` | 从 ESP32 串口打 `WSGAME ...` 调试行；正式出货想静默改成 0 |

> 本表只说每个宏"干什么"：**数值/开关档位一律看 `bsp_config.h` 第 10 节**，本文档不抄。

**怎么确认逻辑跑起来了**（`WSGAME_TRACE = 1` 时，ESP32 串口会看到）

```
WSGAME START step=100ms spawn=600ms shot=15ms maxshots=8   上电/开局那一下（游戏接管灯带）
WSGAME SPAWN color=GREEN idx=119 blocks=1                  远端冒出一颗新灯
WSGAME SHOT color=GREEN shots=1                            按 Key2 发射一颗绿子弹
WSGAME HIT color=GREEN idx=87 score=1 left=3               打中同色 -> 两颗消失 + 数码管 +1
WSGAME MISS near-end misses=1 left=2                       没消掉, 走到近端 -> 漏掉(不扣分)
WSGAME SHOT full color=BLUE max=8                          天上子弹已满: 这一发不响应
WSGAME BLOCK my=GREEN cell=BLUE idx=61 shots=0              撞上异色: 子弹自己消失(色块留着)
WSGAME STOP score=5 hits=5 misses=2                        收局(GAME STOP / 关机)
```

* 数码管：开局显示 `0000`，每命中一次 +1。
* 随时可查快照：`GAME` → `GAME RUN state=RUN blocks=17 shots=2 step=100ms spawn=600ms shot=15ms score=3 hits=3 miss=1 spawned=21`。
* 手感调整（都不用重新编译）：`GAME SPD 200`（运输带慢下来）、`GAME SPAWN 900`（灯稀一点）、
  `GAME SHOT 10`（子弹快一点）。

**已知取舍**

* 漏掉**不扣分**、也不结束；想加惩罚 / 连击，只改 `app_wsgame.c` 的 `shot_check()` /
  `track_tick()`（漏掉那一段）。
* 运输带**填满整条**时远端口子会暂停补灯（等前面消掉 / 漏掉腾位置），不会覆盖已有的灯。
* 得分直接写数码管；若同一时刻手发 `DISP` 命令，最多一帧画面被搅乱（下一次计分自动恢复）。
* 游戏在跑时，`FX` / `FILL` / `LED` 这几个"直接改灯带"的命令会**先停止游戏**再执行
  （应答里带 `(game stopped)`），否则命令生效一帧（`WSGAME_FRAME_MS`）后就被游戏的下一帧覆盖了；
  `BRT` 不用停游戏（亮度对游戏同样生效，游戏下一帧就用新亮度重画）。
* 游戏与效果层共用同一条灯带，但同一时刻只有一个在画：开局时效果层被切到 `LED_FX_OFF`,
  收局时按开局前记录的效果还原（上电本来就是 `OFF` 时按 `COMET` 还原）。

## 4. 远程命令协议（`app_cmd`，示例业务代码）

WiFi 端（ESP32-C3）透传 ASCII 文本行，**命令不区分大小写**，以 `\n` 或 `\r\n` 结束：

| 命令 | 说明 | 应答 |
|---|---|---|
| `PING` | 连通性测试 | `+PONG` |
| `STATUS` / `?` | 查询状态 | `STATUS fx=.. brt=.. spd=.. rgb=.. keys=0x.. up=.. frame=.. rx=.. ovf=..` |
| `FILL r g b` | 整条灯带单色（游戏在跑时先停止游戏） | `OK FILL r g b` |
| `LED start count r g b` | 指定区段上色（同上） | `OK LED start count` |
| `FX n` | 切换效果 0~6（OFF/SOLID/RAINBOW/COMET/BREATHE/BLINK/CHASE）（同上） | `OK FX n NAME` |
| `BRT 0..255` | 亮度（游戏与效果层都生效） | `OK BRT v` |
| `SPD 200..8000` | 动画周期(ms) | `OK SPD v` |
| `GAME` / `GAME STATUS` | **消消乐**：查运行状态/场上灯数/在飞子弹/三个速度/得分 | `GAME RUN state=RUN blocks=17 shots=2 step=100ms spawn=600ms shot=15ms score=3 hits=3 miss=1 spawned=21` |
| `GAME START` / `GAME STOP` | 开局（重开一局，分数清零）/ 收局（清屏，灯带交还效果层） | `OK GAME START (step=100ms spawn=600ms shot=15ms maxshots=8)` / `OK GAME STOP (strip back to fx)` |
| `GAME SPD <ms>` | **运输带速度**：灯每挪一颗灯的毫秒数（越大越慢；范围 `WSGAME_TRACK_STEP_MIN`~`MAX`） | `OK GAME SPD <ms>` |
| `GAME SPAWN <ms>` | **远端口子**：每多少毫秒冒一颗新灯（范围 `WSGAME_SPAWN_MIN`~`MAX`） | `OK GAME SPAWN <ms>` |
| `GAME SHOT <ms>` | **子弹速度**：每飞一颗灯的毫秒数（越小越快；范围 `WSGAME_SHOT_STEP_MIN`~`MAX`） | `OK GAME SHOT <ms>` |
| `VOICE id` | 播放语音（自动选 Key/串口） | `OK VOICE id KEY/UART` |
| `VKEY 0..2` | 直接触发 K1~K3（本硬件标准品没开放 Key 口 → `ERR VKEY unavailable`） | `OK VKEY n` |
| `VPLAY 0..65535` | 按索引播放（默认 `A6` 播 **U 盘**，`WT2003_PLAY_USE_UDISK` 选；校验码自动算，用于逐个索引扫） | `OK VPLAY n (A6 U-disk, see WTRX)` |
| `VPLAY6 0..65535` / `VPLAY0 0..65535` | 强制 `A6`(U 盘) / `A0`(SPI Flash) 播指定索引（对照组，确认音频在哪块介质） | `OK VPLAY6 n (A6 U-disk, see WTRX)` |
| `VOL 0..31`、`VSTOP`、`VPAUSE`、`VNEXT`、`VPREV` | 音量 / 播放控制 | `OK ...` |
| `VNAME [n]` | **按文件名播放（`A7`，本模块唯一能播指定语音的路，见 8.9）**：不带宽参 = 列出 `WT2003_NAME_CYCLE_LIST`；带宽参 `n` = 立刻播第 n 个（文件名须 4 字符放 U 盘根目录） | `OK VNAME n=5 every=4000ms` / `OK VNAME 3 = "T003" (A7 U-disk by name, see WTRX)` |
| `VNAMEON` / `VNAMEOFF` | 开 / 关"每 `WT2003_NAME_CYCLE_MS` 毫秒播下一个文件名"的自动轮播 | `OK VNAMEON 5 files, 4000 ms each` |
| `VOUT 0|1` | 音频输出 SPK(0) / DAC(1)（B6 命令） | `OK VOUT SPK` / `OK VOUT DAC` |
| `VQRY VER|VOL|ST|FILES|CUR` | 发查询命令(C0/C1/C2/C3/C9)，应答看 `WTRX` | `OK VQRY VER (see WTRX)` |
| `VCHECK` | **一键体检**：依次发 C0/C1/C2/`C3`/**CA/C7**/C9/**CB**，回帧原始字节+解析自动打到 ESP32（重点看 `conn=` 与 `udisk_files=`） | `OK VCHECK (see WTRX/WTRXINFO)` |
| `WTRAW <hex...>` | **原样**发一帧给 WT2003（自定义帧，免重烧试协议，见 8.3） | `OK WTRAW <HEX> (n bytes)` |
| `DISP 1234` | 数码管显示（≤4 字符） | `OK DISP ...` |
| `KEYLED <0..3|ALL> r g b [周期ms]` | 按键灯（带周期即闪烁） | `OK KEYLED` |
| `KEYLED DIAG` | 按键灯诊断：实测时序/极性/每路设定色与输出色 + 数据线自检 `line low=/high=`（排查发白） | 多行 `KEYLED ...` |
| `KEYLED T0H <ns>` | 现场改 0 码高电平，立即生效（超范围会被夹回，范围 = `drv_keyled.c` 的 `KEYLED_T0H_MIN/MAX_NS`） | `OK KEYLED T0H x T0L y T1H z T1L w` |
| `KEYLED T0L <ns>` | 现场改 0 码低电平，立即生效（`KEYLED_T0L_MIN/MAX_NS`） | 同上 |
| `KEYLED T1H <ns>` | 现场改 1 码高电平，立即生效（`KEYLED_T1H_MIN/MAX_NS`，且必须 ≥ `T0H + KEYLED_T1H_GAP_NS`） | 同上 |
| `KEYLED T1L <ns>` | 现场改 1 码低电平，立即生效（`KEYLED_T1L_MIN/MAX_NS`） | 同上 |
| `KEYLED INVERT <0/1>` | 数据线极性（线上串了反相器/三极管时用 1），立即生效 | `OK KEYLED INVERT x` |
| `HEARTBEAT ms` | 周期心跳上报（0=关闭） | `OK HEARTBEAT ms` |
| `POWER OFF` | 远程关机 | `OK POWER OFF`（随后断电） |

STM32 主动上报：

```
EVT KEY <id> <DOWN|UP|SHORT|LONG|HOLD> <ms>
EVT POWER SHORT
READY LEDAnipop fw=1.0 led=120        (上电第一条)
HB <uptime_ms> <fx> <brt>             (开启 HEARTBEAT 后)
WSGAME START/SPAWN/SHOT/HIT/MISS/BLOCK/STOP (消消乐, WSGAME_TRACE=1 时, 见 3.9)
```

按键的本地联动（按下点亮对应按键灯、松开熄灭）也在 `app_cmd.c` 的 `app_key_callback()` 里，可按项目需要随意改；
**消消乐运行时按键灯由 `app_wsgame` 接管**，这里会自动让位（判据是 `wsgame_is_running()`）。

## 6. 已知的假设与限制（请按实物核对）

1. **芯片**：按工程现有配置为 **STM32F103RCT6**（你描述的 "STM32g4F103RCT6" 应是笔误）。
   若实际是 STM32G4，本目录的 StdPeriph 代码不能直接用，需要换成 HAL/CubeMX 工程。
2. **WT2003HX 串口协议**：已按《WT2003HX 芯片》手册对齐（帧 `7E 长度 命令 数据 校验码 EF`，
   长度含自身；命令码见 3.6 节）。固件命令码不同时，只改 `drv_wt2003h.h` 的 `WT2003_CMD_*`。
3. **PC3 电源自锁极性**：`POWER_HOLD_ON_LEVEL=1`（高电平维持供电），低有效时改成 0。
4. **按键灯颜色异常**先用 `KEYLED DIAG` 看四段时序 / 极性 / 每路颜色，再用
   `KEYLED T0H/T0L/T1H/T1L/INVERT` 现场扫（上电已经用 DWT 做过四段自标定，正常不用动
   `KEYLED_CYC_COMP`）；注意 0 码 / 1 码的**低电平也要落在手册范围内** —— 不要再按
   “固定 1.25µs 位周期”去反推 `T1L/T0L`（那样 `T1L` 会被压到 300ns 以下，灯珠直接判错）。
   灯带整体颜色错位时检查 `WS2812_T0H_NS/T1H_NS` 与灯珠型号（GRB 顺序）。
5. **WS2812 帧间复位**已按规格书取值（`WS2812_RESET_US`）；只有确认灯珠能吃 50µs 复位、想提高帧率时才往小调。
6. 按键**组合键**未实现，需要时在 `drv_key_process()` 里加一层判定即可。
7. 数码管是**静态显示**（4 片 595 各管一位），没有动态扫描，因此没有刷新中断。

## 7. 联调建议

| 现象 | 检查点 |
|---|---|
| 灯带不亮 / 只有第一颗亮 | 先敲 `STATUS` 看 `frame=` 是否在涨（涨→固件侧没问题，直接查硬件）；再按 **3.2.1 节**的 3 步自检 + 现象对照表逐条对号入座 |
| 灯带颜色错位、闪烁 | `WS2812_T0H_NS/T1H_NS`；帧间复位时间；供电与地线是否够粗 |
| 按键不响应 | 内部上拉是否生效（`GPIO_Mode_IPU`）；`drv_key_process()` 是否在主循环被调用 |
| 按键灯颜色不对 / **三颗一起发白** | 先按 3.3 节“全白四种情况”表定性（`KEYLED ALL 0 0 0` 与 `ALL 255 255 255` 各发一次，看灯**是否理你**、黑白是否颠倒）：**恒白且命令全不理** = 帧没被锁存 → 先 `KEYLED INVERT 1` + 量 DIN 空闲电平/高电平幅值，**别**先去调时序；能看出深浅变化才是位判错 → 再 `KEYLED DIAG`（看四条相位与极性），现场扫 `KEYLED T0H/T0L/T1H/T1L <ns>`（**以当前值为中心、两个方向各挪一档**）和 `KEYLED INVERT 1`（改完立即生效，好用再写回 `bsp_config.h`）；高、低电平四条相位都要落在手册内，别只调高电平；确认刷新后的复位时间够（`KEYLED_RESET_US`）、输出期间中断已关闭；先用 `KEYLED 0 0 0 255` 单颗试色 |
| 串口收不到命令 | 波特率 115200；`esp32_rx_overflows()` 是否在增长（增长说明主循环太慢或被长时间关中断） |
| 数码管顺序反了 | `HC595_DIGIT_REVERSE`（=1 倒序，本板默认值，`bsp_config.h` 第 6 节）、`hc595_digit_map[]` |
| 上电自锁不住 | `POWER_HOLD_ON_LEVEL` 极性、PC3 与硬件自锁电路的接法 |
| WT2003 完全没声音、`WTST` 显示 `rx=0` | 模块**一句都没回**：PB10→模块RXD、PB11←模块TXD、**共地**、9600 8N1、模块是否被设成串口控制模式 |
| WT2003 串口能看到 `WTRX ...` 回帧但仍无声 | UART/协议/接线已通 → 转查**音频侧**：模块里有没有音频文件、曲目号规则、DAC/功放/喇叭、音量；先敲 `VCHECK`（`files=` / `volume=` / `cur_file=`）再用 `VPLAY 0/1/2…` 逐个索引试（详见第 8 节） |

调试灯带时序时，建议先用 `led_fx_set(LED_FX_SOLID)` + `ws2812_set_pixel(0,255,0,0)` 确认底层时序正确（只有第一颗红、其余灭），再开动画效果。

* 若你的板子不方便用 TIM2，可以把 `bsp_time.c` 里的 `BSP_TIME_TIM` 换成 TIM3/TIM5（注意别和灯带的 TIM4 冲突）。

## 8. WT2003 语音排查（协议已按手册对齐）

> **⚠ 先看这两条（第五轮定论，完整判读见 8.9）**：
> 1. `A0`（SPI Flash 索引）会被模块当"指定曲目不存在"拒绝（回 `02`）—— 本工程音频在 **U 盘**上，
>    用 `A0` 自然全程无声；8.4~8.6 里"模块播不了文件 / 曲目索引没建立"的结论是**在命令用错的前提下**得到的。
> 2. **但 `A6`（指定 U 盘根目录索引播放）在本模块上也不出声**：它收下命令、回一个固定字节 `05`，
>    却从不播放（索引 1 / 2 / 99 / 0 全试过，`cur_file` 从不因它变化）；而 `AC` / `AD`（下一曲 / 上一曲）
>    从停止态都能出声 ⇒ 播放引擎与音频链路正常，**只有"按索引指定曲目"这条路不通**。
>    ⇒ 正式播指定语音改用 **`A7` 按文件名播放**（文件名固定 4 字符、放 U 盘根目录）：
>    `wt2003_play_udisk_name("T001")` / 远程 `VNAME <n>`，配置与判读见 8.9.2。
> 现场对照：`VNAME 1` 应有声；`VPLAY6 1`（A6）/ `VPLAY0 1`（A0）都不出声。

### 8.1 看收发帧（`WT2003_TX_TRACE` / `WT2003_RX_TRACE`，仓库默认都是 0 = 关闭）
`Inc/bsp_config.h` 里这两个开关打开时，`main.c` 会把**每一次收/发**都从
**ESP32 串口（USART1, 115200）** 打一行 ASCII：

```
WTTX 7E 05 A0 00 01 A6 EF    主机真正发出去的原始字节(每次发帧都打)
WTRXRAW 7E 04 A0 00 A4 EF    模块回帧的原始字节(含 7E/长度/校验码/EF)
WTRX A0 00                   同一帧解析后的结果: 命令码 + 数据区
WTRX C1 1F                   命令码 0xC1(查询音量), 数据区 1F(=音量 31)
WTRXINFO A0(SPI-Flash) ret=0x02 = EMP (no such file)        解析成人话(见 8.4 / 8.7)
WTRXINFO A6(U-disk) ret=0x05 = 0x05 (undocumented; ... audio still plays)   ★ 非 0 ≠ 没播!
WTRXINFO flash_files=5 (SPI-Flash, 1-byte reply; compare with C7)  C3 的解析(实测只回 1 字节)
WTRXINFO udisk_files=5 (U-disk, 1-byte reply) [ok: ...]      C7 的解析 <== 本工程看这条
WTRXINFO conn=0x00 PC=0 UDISK=0 FLASH=0                      CA 的解析(要连 C7 一起看)
WTRXINFO cur_file=1 / volume=31 / status=0x02 [STOPPED]      C9 / C1 / C2 的解析
WTRXINFO ver=........ (len=26, hex 见上面的 WTRX 行)          C0 的解析(长回帧, 见 8.4)
WTRXBAD 7E 1A C0 ...         结构不对的回帧(帧尾不是 EF / 帧长超缓冲)也原样打出来
```

* **判据 0（先看有没有 WTRXBAD）**：`WTRXBAD` 行 = 模块回的字节**没能按手册格式解析**，
  例如长度字节口径不同、或整帧比 `WT2003_RX_FRAME_MAX` 还长。以前这类字节会被驱动**静默丢掉**，
  表现为"`WTST` 的 `rx=` 一直在涨，却一行 `WTRXRAW` 都没有"——看到 `WTRXBAD` 就以它为准。

* **判据 1（长度字节）**：手册 5.1.2.2 的原例是
  `发→ 7E 05 A0 00 01 A6 EF` / `收← 7E 04 A0 00 A4 EF`。
  主机发 `A0` **必然带 2 字节曲目号**（长度 05 = 1 自身 + 1 命令 + 2 数据 + 1 校验码）；
  模块回帧的长度只有 **04**（1 个数据字节）。所以看到 `7E 04 A0 xx ...` 是**模块的回帧**，
  不要当成主机发出去的帧。
* **判据 2（看谁在写缓冲）**：调试器里的 `s_rx_buf` 是驱动的**接收**环形缓冲
  （`drv_wt2003h.c`，`WT2003_RX_BUF_SIZE` = 128 字节；ESP32 的那个才是 512 字节），
  它是"模块 → MCU"的字节，还带上一帧的残留。想要"这一帧的干净原貌"用
  `wt2003_last_rx_raw(&len)`（`WTRXRAW` 行就是它），想要"主机发了什么"看 `WTTX` 行。
* 驱动按手册格式 `7E 长度 命令 数据 校验码 EF` 解析，`WTRX` **已剥掉命令码与校验码**，
  打印的就是纯数据区。
* 没有输出 = 模块没有回话，这就是最直接的判据；也可以用远程命令 `WTST` 看累计 `rx=` 字节数。
* 关闭：把两个开关都改成 0（**仓库默认就是 0**，正式固件免得占串口带宽；置 1 才有下面这些行）。

> 想确认"A6 到底发了几个字节"：把 `WT2003_TX_TRACE` 置 1 重烧，敲 `WTRAW 7E05A60001ACEF`
> 或跑 `WTPROBE 8`（自检表第 8 步 = `A6` 播 U 盘索引 1），串口应打出
> `WTTX 7E 05 A6 00 01 AC EF` —— 7 字节、长度 05。

### 8.2 由现象定位（按顺序做）

| 现象 | 结论 / 下一步 |
|---|---|
| `WTST` 的 `rx=0`（模块一句都没回） | 查 TX 线（PB10 → 模块 RXD）、**共地**、`WT2003_BAUD` = 9600、模块是否处于串口控制模式 |
| `rx` 在涨但没有 `WTRXRAW`，只有 `WTRXBAD` | 模块回帧**格式与手册不一致**（长度字节口径 / 帧长超 `WT2003_RX_FRAME_MAX`）→ 按 `WTRXBAD` 的原始字节对着手册核，别怀疑接线 |
| 自检第 1 步（`AB` 停止）之后、第 8 步（`A6`）之后才出声 | 模块此前卡在"播放/忙"（查询 `C2` = `02`）→ 正式固件上电应先 `VSTOP` 再播提示音 |
| 第 2 步（`B6 01` DAC）无声、第 3 步（`B6 00` SPK）才出声 | 模块此前处于 DAC 输出 → 用 `VOUT 0` 固定为 SPK，或核对喇叭接法 |
| `A6` 全回 `05` 且**全程无声**，但 **`AC` / `AD`（下一曲 / 上一曲）出声** | **第五轮定论（见 8.9）**：本模块 `A6` 收下命令但不播 → 改用 `A7` 按文件名播放（`VNAME <n>` / `wt2003_play_udisk_name("T001")`），不必再去折腾索引排序或厂商上位机 |
| `A6` 回 `01`（索引 0）、`A6` 回 `02`（索引 1~5）都没声，`AA`/`AC` 也没声 | 模块**播放不了它里面的文件**（不是索引问题）：文件格式/采样率/码率不被支持、或文件系统被半途拔线写坏 → 用厂商上位机＋标准 MP3 重灌（见 8.4） |
| `A6` 回 `00`（`ret=0x00`）但仍无声 | 播放已被接受 → 完全转音频侧：音量（`C1`）、输出方式（`B6` = SPK）、功放供电/使能脚、喇叭是否接在 `SPK` 13/14 脚、共地 |
| 查询回来 `files=0`（`C3` 回 `00`） | 模块**没认到文件**：格式 / 命名 / 目录不符合模块要求，用厂商上位机重新灌 |
| `WTRX A6 05`（或 `D2 05`） | 手册 4.1.3.1 只定义 `00/01/02`，`05` 是本固件私有的固定应答，**既不代表成功也不代表失败**；但第五轮实测 `A6` 回 `05` 时**确实一声都没有**（见 8.9）→ 别再用 `A6`，改 `VNAME <n>`（`A7`） |
| `WTRX A6 xx` 且 `xx` = `01` / `02` | 手册口径的**真失败**（`01` = 出错不执行 / `02` = 无此文件）：`VSTOP` → `VCHECK`（文件数 / 音量 / 当前文件）→ `VPLAY 1/5…` 扫索引，详见 8.4 |
| 索引对不上 | `VQRY FILES` / `VCHECK` 看文件总数（`udisk_files=`）、`C9` 看当前文件；**播指定语音用 `VNAME <n>`**（`A7` 按文件名，不受索引顺序影响），别用 `A6`（见 8.9） |

> `WTRX C1 xx` 的 `xx` 就是模块当前音量；`WTRX C2 xx` 是工作状态（实测 `02`）；
> `WTRX C3 xx` 是文件总数 —— **实测模块只回 1 字节**（`7E 04 C3 05 CC EF` = 5 个文件），
> 驱动对 1 字节和 2 字节两种回法都做了兼容解析。

### 8.3 免重烧试任意帧（`WTRAW`）
`wt2003_send_raw()` 挂在远程命令上，**不改代码、不重烧**就能把手册里的任意帧发给模块：

```
WTRAW 7E05A60001ACEF          # A6 播 U 盘索引 1（本工程音频在 U 盘）
WTRAW 7E 05 A6 00 01 AC EF    # 空格分隔；也接受 0x7E / 逗号 / 冒号
WTRAW 7E05A00001A6EF          # A0 播 SPI Flash 索引 1（对照用）
WTRAW 7E04AE1FD1EF            # AE 音量 = 31
WTRAW 7E04B600BAEF            # B6 切 SPK
```

* 应答 `OK WTRAW 7E05A00001A6EF (7 bytes)` = 已发出；`ERR WTRAW HEX ...` = 十六进制没解析出来；
* 模块回帧打印成 `WTRX ...`；`WTST` 可看 `rx=` / `cmd=` 计数。

### 8.4 实测案例：日志全对、有回帧，但一点声音都没有

现场日志（ESP32 串口 115200，`WT2003_TX_TRACE` / `WT2003_RX_TRACE` = 1）：

```
READY LEDAnipop fw=1.0 led=120
WTTX 7E 04 AE 1F D1 EF        ① 上电设音量 31（手册 5.1.2.7 原例, 4 字节）
WTTX 7E 05 A0 00 01 A6 EF     ② 上电播索引 1（手册 5.1.2.2 原例, 7 字节, 长度 05）
WTRXRAW 7E 04 AE 00 B2 EF     ③ AE 回帧: 长度 04, 数据 00
WTRXRAW 7E 04 A0 02 A6 EF     ④ A0 回帧: 长度 04, **数据 02**
WTRX A0 02
WTRXINFO A0 ret=0x02 (NOT started: send AB first, then check file/index)
```

再敲一次 `VCHECK`（把 C0/C1/C2/C3/C9 全查一遍），现场回帧：

```
WTTX 7E 03 C1 C4 EF
WTTX 7E 03 C2 C5 EF
WTTX 7E 03 C3 C6 EF
WTTX 7E 03 C9 CC EF
WTRXRAW 7E 04 C1 1F E4 EF      C1 回帧: 数据 1F = **音量已经是 31（最大）**
WTRXINFO volume=31 (0=silent, 31=max)
WTRXRAW 7E 04 C2 02 C8 EF      C2 回帧: 数据 02 = **不是空闲状态**
WTRXINFO status=0x02 (non-idle; 0x02 seen while A0 also replies 02)
WTRXRAW 7E 04 C3 05 CC EF      C3 回帧: 长度 04 → **只有 1 个数据字节**，05 = **模块认到 5 个文件**
WTRXINFO files=5 (1-byte reply; 0 = module sees no files)
WTRXRAW 7E 05 C9 00 01 CF EF   C9 回帧: 长度 05（2 字节数据）0001 = 当前文件 1
WTRXINFO cur_file=1
```

判读（这套日志已经能排除一半的怀疑方向）：

* ①② 证明**主机发送侧完全正确**：`A0` 就是 2 字节索引、长度 05，与手册逐字节一致；
  而且模块每次都有回帧，说明波特率 / 接线 / 共地也没问题。
* ③④ 是**模块的回帧**（长度 04，不是主机帧；主机帧长度必然是 05）。
* ④ 的数据字节是模块的**处理结果**：手册示例里这里是 `00`，实测是 `02`
  → **模块没有真正开始播放**，"没声音"的原因在模块侧（文件 / 索引），不在 MCU 侧。
* ③ `AE` 的回帧数据是 `00`，表示音量命令被接受（返回值口径见手册 5.1.2.7）。
  **它不等于当前音量** —— 想知道真实音量必须用 `C1` 查询（`VCHECK` 会打 `volume=`）：
  音量是**掉电记忆**的，若模块存的是 0（静音），播放"成功"也一样听不见。
* 文件是**用 USB 把模块当 U 盘拷进去**的（模块里确实有音频）→ 那么 `A0` 回 `02` 基本只剩
  **文件规则 / 索引号**问题：模块内的索引顺序由它扫描文件系统的顺序决定，**不一定等于文件名里的数字**。
  用 `VCHECK` 看 `files=`（模块认到几个文件），再用 `VPLAY 0/1/2…` 找到回 `ret=0x00` 的那个索引；
  若 `files=0`，则是文件**格式 / 命名 / 目录**不被模块认（对照手册的命名与格式要求重灌）。

`VCHECK` 之后方向就基本唯一了：

* 音量 = `1F`（31，最大）、文件数 = `05` → **"静音"和"没文件"这两个最常见的怀疑都被排除**。
* `C2`（状态）回的 `02` 与 `A0` 被拒时回的 `02` 是**同一个值** → 当时推测模块**一直认为自己"忙于
  播放/未就绪"**（例如上一次播放被中途打断后没清理），于是对任何新的 `A0` 都回 `02`。
  这种状态下继续扫索引没有意义，必须**先发 `AB` 停止清状态**再发 `A0`。
* 自检序列已按这个顺序改成（上电自动跑）：
  **1 = `AB` 停止 → 2~3 = `B6` 切 SPK → 4 = `AE` 音量 31 → 5~9 = `C1/C3/C9/C0/C2` 查询 →
  10~14 = 播放索引 0~4**；哪一步出声、哪一条回 `ret=0x00`，看日志就能定位。
  > 最终定位：本节及 8.5/8.6 里的 `A0` 是被"命令码用错"拖累的（`A0` 只播 SPI Flash）；本项目音频在 U 盘，
  > 现自检里的试播已全部改为 **`A6`（播 U 盘）**，见第 3.6 节。
  > 这一版跑完后（见 8.5）发现 `AB` 其实**回 `00` 被接受了**、而 `A0` 依旧全被拒，
  > 所以"忙于播放"被排除，序列随即改成 **20 步**（去掉 `C0` 的位置、加上 `AA`/`AC` 绕过索引）；
  > 20 步跑完的现场数据与判读见 **8.6**，序列再升级为 **30 步**；第四轮又加了
  > "返回码取证"（`C3` 对比、不存在的索引、索引 0、`A0`）成为 **38 步**，见 8.7。
* 如果 `AB` 之后 `A0` 仍回 `02`，则是**模块里的"曲目索引"没建立**：`C3` 只是数了文件系统里的文件，
  不代表模块已经把它们排好成"曲目 1/2/3…"。处理办法（按代价从小到大）：
  1. 用厂商上位机把这个 U 盘/模块里的音频**重新排序（生成/更新曲目索引）**；
  2. 或按手册要求把文件重命名（如 `00001.mp3`、`00002.mp3` …）后**重新拷一次**，再上电复位；
  3. 或直接用厂商上位机点播一首，确认模块自己能出声（这一步能彻底排除功放/喇叭/供电）。

按顺序做（全部用远程命令，不需要重烧）：

```
VSTOP          → 先停一次: 清"忙于播放"状态（实测 AB 回 00 = 被接受）
VCHECK         → 一条命令把 C0/C1/C2/C3/C9 全查一遍: 看 WTRXRAW(原始) / WTRX / WTRXINFO
                 （重点: files=? volume=? cur_file=?）
VPLAY 1        → 逐个索引扫（1/5/0…），看哪一条回帧变成 ret=0x00 并且出声
VOUT 0         → 强制切回 SPK 输出（喇叭接模块 SPK 脚 / 内部功放时用）
VOL 31         → 音量设到最大（掉电记忆，可能是 0 = 静音）
WTRAW 7E03AAADEF → AA 播放当前曲目（绕开索引: 出声说明引擎好、是索引问题）
WTRAW 7E03ACAFEF → AC 下一曲（同上）
```

* **模块自己能出声的独立验证**（不依赖本固件）：用厂商上位机让模块播一首
  （自检序列里已无 Key 步骤 —— 本项目标准品 Key 口没引出功能，需厂家定制，`VKEY` 会回 `ERR`）。
  → 能出声说明模块 / 功放 / 喇叭 / 供电都好，问题只在"文件 + 索引号"。
* **模块自己也不出声** → 直接查音频侧：文件格式/采样率是否被模块支持、音量是否为 0、
  喇叭是否接在 `SPK`（13/14 脚）、共地。

### 8.5 第二轮实测（20 步自检：把"索引问题"和"文件问题"分开）

第一轮（14 步）跑完的现场日志（片段）：

```
WTTX 7E 03 AB AE EF
PROBE 1/14 AB stop play (clear stuck busy state) rx=8
WTRXRAW 7E 04 AB 00 AF EF    WTRX AB 00        ← **AB 被接受**(数据 00), "卡在忙"的假设不成立
WTRXRAW 7E 04 AE 00 B2 EF                      ← AE 音量命令被接受
WTRXRAW 7E 04 C1 1F E4 EF    volume=31         ← 音量已是最大
WTRXRAW 7E 04 C3 05 CC EF    files=5           ← 模块认到 5 个文件
WTRXRAW 7E 05 C9 00 01 CF EF cur_file=1
WTTX 7E 03 C0 C3 EF          PROBE 8/14 ... rx=51
WTTX 7E 03 C2 C5 EF          PROBE 9/14 ... rx=77   ← **rx 涨了 26 字节, 却一行 WTRXRAW 都没有**
WTRXRAW 7E 04 C2 02 C8 EF    status=0x02
WTRXRAW 7E 04 A0 01 A5 EF    A0 ret=0x01        ← 索引 0: 回 01
WTRXRAW 7E 04 A0 02 A6 EF    A0 ret=0x02        ← 索引 1~4: 回 02
```

三条新结论：

1. `AB` 回 `AB 00` = 停止命令**被接受** → "模块卡在播放/忙"这个假设**基本不成立**（真被卡住的话，
   `AB` 之后就该能播了；可后面 5 个 `A0` 依然全被拒）。
2. **`A0` 索引 0 回 `01`、索引 1~4 回 `02`** —— 两个**不同**的返回码，说明模块区分了两种情况
   （"索引/参数无效" vs "索引有效但播不起来"）。至少可以确定：模块**认得这些索引**，
   只是**没能真的播放出来** → 嫌疑从"索引号填错"转向"模块播放不了这些文件（格式 / 文件系统）"。
3. `C0`（版本）那 26 字节"收了却没解析"：`WT2003_RX_FRAME_MAX` 原来是 16，而 C0 的回帧比它长，
   整帧被驱动**静默丢掉**（`rx` 一直涨、`WTRXRAW` 一行都没有）。现已把上限提到 32，并新增
   `WTRXBAD` 行打印"结构不对"的回帧（`wt2003_set_bad_frame_handler()`），以后不会再出现
   "字节收了却什么都看不见"。

所以自检序列改成 **20 步**，核心是加两个**绕过索引**的动作（这是把两类原因分开的唯一办法）：

| 步骤 | 发的东西 | 这一步要回答的问题 |
|---|---|---|
| 1 | `AB` 停止 | 清状态（排除"忙"） |
| 2~3 | `B6` DAC → `B6` SPK | 把输出方式修回 SPK（本硬件喇叭接 `SPK` 13/14 脚） |
| 4 | `AE` 音量 31 | 排除"音量掉电记成 0 = 静音" |
| 5~8 | `C1` / `C3` / `C9` / `C2` | 播放前的基准：音量 / 文件数 / 当前文件 / 状态 |
| 9 | `A0` 索引 1 | 按索引播（1-based 第一首） |
| 10~11 | `C9` / `C2` | 播完马上查：当前文件号**动了吗**？状态**变了吗**？ |
| 12 | `A0` 索引 5 | 补测 1-based 的最后一首（1~4 已知回 `02`，只剩 5 没测） |
| 13 | `A0` 索引 0 | 对照（已知回 `01`，用来判断返回码口径） |
| 14 | `AB` 停止 | 回到干净状态 |
| **15** | **`AA` 播放当前曲目** | **绕过索引**：出声 = 引擎好 → 就是索引的问题 |
| 16 | `C2` | 第 15 步到底播起来没有 |
| **17** | **`AC` 下一曲** | 同样绕过索引（让引擎自己选曲目） |
| 18 | `C2` | 第 17 步播起来没有 |
| 19 | `AB` 停止 | |
| 20 | `C0` 版本 | 确认模块型号 / 固件（长回帧，现在能打出来） |

判读只需看两件事：**（甲）第 15 / 17 步有没有声音；（乙）第 10 / 11 步的 `C9` / `C2` 有没有变化。**

* 有声音（哪怕只有一声）→ 模块、功放、喇叭、文件通通没问题，**只是 `A0` 的索引对不上** →
  用厂商上位机**重建曲目索引**（8.4 的办法 1 / 2）。
* `AA` / `AC` 也没声，且第 10 / 11 步 `cur_file` / `status` 毫无变化 → 模块**根本没在播** →
  **文件侧问题**：格式 / 采样率 / 码率不被支持，或文件系统被写坏 →
  用厂商上位机 + 标准 MP3（44.1kHz、CBR、根目录 `00001.mp3`…）重灌一遍。
* 第 20 步的 `ver=` 打出来是什么，也能帮着确认模块是不是本手册对应的型号 / 固件版本。

### 8.6 第三轮实测（20 步自检的现场日志）

20 步自检跑完的现场日志（要点，`rx` 累计 131 字节）：

```
WTRXRAW 7E 04 AB 00 AF EF              WTRX AB 00    ← AB(停止) 被接受
WTRXRAW 7E 04 AA 00 AE EF              WTRX AA 00    ← **AA(播放/暂停) 也回 00 = 被接受!**
WTRXRAW 7E 04 AC 01 B1 EF              WTRX AC 01    ← AC(下一曲) 回 01
WTRXRAW 7E 04 A0 02 A6 EF              WTRX A0 02    ← A0 索引 1 / 5 都回 02
WTRXRAW 7E 04 A0 01 A5 EF              WTRX A0 01    ← A0 索引 0 回 01
WTRXRAW 7E 05 C9 00 01 CF EF           cur_file=1    ← 从头到尾没变过
WTRXRAW 7E 04 C2 02 C8 EF              status=0x02   ← 从头到尾没变过
WTRXRAW 7E 18 C0 57 54 53 32 35 31 ... 81 EF
                                       ver=WTS251016-70-A01V4.01 (len=21)
```

**重点：全部无声（连一声"咔哒"都没有），但几乎所有命令都被回 `00`（成功）。**

先把协议这件事钉死（这一条能省掉大量弯路）：

* `C0` 的回帧 `7E 18 C0 "WTS251016-70-A01V4.01" 81 EF`，按手册口径验算校验和 ——
  `0x18 + 0xC0 + Σ(21 个字符) = 0x581`，低字节 **`0x81`**，与帧里印的校验码**完全一致**。
  → **帧格式、波特率、收发接线全部正确**，问题不在通信层。
* 版本串 `WTS251016-70-A01V4.01` 说明这是**厂家定制固件**（`WTS251016` 像生产批次/日期），
  它的行为不一定等同于公开手册里的标准固件（例如可能被配置成**上电自动播放**）。

于是原因被压缩成两条路，第三轮 30 步自检就是用来劈开它们的：

| 观测点 | 说明什么 |
|---|---|
| 第 13 步 `A0` 在 `AA`（暂停）之后**回 `00`** | 第 8 步的 `02` 是**"忙碌拒绝"** → 模块**其实一直在播**（多半是上电自动播放）→ 问题在**音频输出侧**（见下） |
| 第 18 / 21 步（DAC 通路 / SPK 通路各试播一次）有没有声 | 有声的那一档 = 正确的输出方式 / 接法；两档都无声 → 功放 / 喇叭 / 供电 |
| 第 10 / 11 / 24 / 26 步 `C9`/`C2` 的 `CHANGED!` | 变了 = 引擎真的在动（换曲 / 播放）; 一直 `UNCHANGED` = 引擎根本没动 |
| 第 27 / 28 步 `A0 01 01` / `A0 02 01` | 试探 `A0` 两个数据字节的第一个是不是"存储介质 / 盘号"（Flash/TF/U盘 三选一的固件） |

**硬件侧同时要排的三件事**（很多"命令全对但没声"最后都是这里）：

1. **喇叭必须接 `SPK+` 与 `SPK-` 两端**（模块内部是 BTL 桥接功放）。
   只接 `SPK+`/喇叭另一端接 `GND` 会**永远无声**，而且模块自检完全正常。
2. 供电与共地：模块 `VCC`（3.3V / 5V 按板子）要稳，和 MCU **共地**（串口能通说明已共地）。
3. 上电后**贴近喇叭听**：若有轻微底噪/电流声 = 功放已工作、只是没有解码输出；完全死寂 = 功放/喇叭回路断。

判读（对应处理办法）：

* **第 18 或 21 步有声音** → 输出方式/接法确定，回去查正式流程为什么不出声（见 8.10 的收尾；
  第五轮结论见 **8.9**：本模块 `A6` 不出声，正式播指定语音要用 `A7` 按文件名）。
* **两档都没声、`C9`/`C2` 一直 `UNCHANGED`** → 模块**根本没在播**，且 `A0` 的 `02` 不是"忙"而是
  "无法播放该文件" → 文件侧：格式 / 采样率 / 码率不被支持，或文件系统被写坏 →
  用厂商上位机 + 标准 MP3（44.1kHz、CBR、根目录 `00001.mp3`…）重灌，重灌后**重新上电**。
* **两档都没声但 `AA` 回 `00` / `AC` 回 `01`** → 命令被接受却没输出，重点转向**硬件**（上面 1~3 条），
  尤其 `SPK` 的 BTL 接法；也可用厂商上位机**独立验证**模块自己能不能出声（这一步能把固件与硬件彻底分开）。
* 出现新的 `WTRXBAD` 行 → 回帧长度/帧尾与手册口径不同，把整行发出来分析（`WT2003_RX_FRAME_MAX`
  已提到 32，不会再有"字节收了却看不见"的情况）。

### 8.7 第四轮实测（38 步：U 盘口径 + 返回码取证）

现场日志（要点，`PROBE DONE rx=190`；每一步的原样字节都能在 `s_probe_tab` 里对上）：

```
WTTX 7E 04 D2 02 D8 EF        WTRX D2 05      ← D2 切盘符 = U 盘: 回 0x05(手册示例是 00)
WTTX 7E 04 B6 00 BA EF        WTRX B6 00      ← B6 输出 = SPK: 回 00
WTTX 7E 04 AE 1F D1 EF        WTRX AE 00      ← AE 音量 31: 回 00
WTTX 7E 03 C1 C4 EF           WTRX C1 1F      ← volume=31 (音量已满)
WTTX 7E 03 CA CD EF           WTRX CA 00      ← conn=0x00: PC=0 UDISK=0 FLASH=0
WTTX 7E 03 C7 CA EF           WTRX C7 05      ← udisk_files=5   ★ 和上一条自相矛盾!
WTTX 7E 03 C9 CC EF           WTRX C9 00 01   ← cur_file=1
WTTX 7E 03 C2 C5 EF           WTRX C2 02      ← status=0x02 = STOPPED
WTTX 7E 05 A6 00 01 AC EF     WTRX A6 05      ← A6 试播索引 1: 回 0x05(手册示例是 00)
WTTX 7E 03 AC AF EF           WTRX AC 00      ← 下一曲
WTTX 7E 03 C9 CC EF           WTRX C9 00 02   ← cur_file=2 (CHANGED!)
WTTX 7E 03 AD B0 EF           WTRX AD 00      ← 上一曲
WTTX 7E 03 C9 CC EF           WTRX C9 00 01   ← cur_file=1 (CHANGED!)
```

**现场结论：这几步里喇叭确实出声了。**

三条钉死的判读：

1. **通信层 100% 正常**：每条命令都拿到了结构自洽的回帧（`长度 = 长度+命令码+参数+校验和`，
   校验和 = 前三者累加和的低字节），且回帧里的 `cmd` 一定是刚发出去的那条 —— 没有错帧、没有丢帧。
   所以"没声音"这件事从来不在 MCU 侧（`C0` 版本帧的校验和也完全吻合，见 8.6）。
2. **本固件的返回码口径 ≠ 手册**：手册 4.1.3.1 只定义 `00 = OK / 01 = FAIL(出错, 不执行) /
   02 = EMP(无此文件)`，而实测 `D2 / A6 / C7` 都回 `0x05`，同一轮里**音频照样播出来了**。
   （巧合的是 `0x05` 正好等于 `CA` 连接位图里的 `bit2(U盘) | bit0(Flash)`；
   不管它到底表示什么，**都不能当成失败**。）第 31~38 步就是用来钉死它的。
3. **`CA` / `C2` 这两条查询在本固件上不完全可信**：
   * `CA = 00`（U 盘位 = 0）却 `C7 = 05`（U 盘上 5 个文件）—— 同一轮里自相矛盾；
   * `C2` 全程 `02 = 停止`，可 `AC` / `AD` 明明把 `cur_file` 从 1 推到 2 又推回 1。
   ⇒ 判断**介质**看 `C7`（文件数非 0 = 模块真扫到了文件），判断**有没有声**看**耳朵**，
   别只看 `CA` / `C2`。

第 31~38 步要回答的问题（跑完把日志发出来即可）：

| 步 | 发的东西 | 想看到什么 |
|---|---|---|
| 31 | `C3` | 和第 7 步 `C7` 对比 —— **实测两条口径一样（都回 `05`，均 1 字节）**，所以 `C3` 不是 Flash/U 盘判别位（手册虽写 Flash，本模块不成立） |
| 32 | `A6 00 63`（索引 99，绝不存在） | 若回 `02` ⇒ 手册返回码表在本固件生效，那 `0x05` 只是"U 盘类命令的另一种应答"；<br>若也回 `05` ⇒ 本固件返回码口径完全另说，一切以耳朵为准 |
| 33 | `C2` | 那次"失败"的 `A6` 有没有影响状态 |
| 34 | `A6 00 00`（索引 0） | 索引从 0 还是从 1 开始（手册 4.1.4.5 示例写"索引 `0001` = 第 2 首"）—— **听** |
| 35 | `C2` | 短间隔再查：有没有变成 `01 = 播放` |
| 36 | `A0 00 01`（Flash 索引 1） | Flash 里真没文件时应回 `02`，交叉验证第 31 步 |
| 37~38 | `C9` / `C2` | 收尾 |

出声了也别省这两条硬件复核（最容易反复）：

* 喇叭接 **`SPK+` 与 `SPK-` 两端**（模块内部是 BTL 桥接功放）；任一端接 `GND` 会变成
  "时响时不响"甚至完全无声，而自检看上去一切正常。
* U 盘：`D+` / `D-` / `5V` / `GND` 四根都要接，格式 **FAT / FAT32**，音频放**根目录**，
  索引按文件拷贝顺序排；`C7` 回非 0 才能证明模块真的扫到了。

### 8.9 第五轮实测（**根因定论**：本模块 `A6` 收下命令但不出声 → 改用 `A7` 按文件名播放）

第五轮把自检缩到"只会出声的那几步"逐条听，结果非常干净：

| 自检步 | 发出的命令 | 耳朵听到的 |
|---|---|---|
| 25 | `AC` 下一曲 | **有声**（第 26 步 `C9` 由 1 → 2） |
| 27 | `AD` 上一曲 | **有声**（第 28 步 `C9` 由 2 → 1） |
| 10 / 15 / 20 / 23 / 29 / 32 / 34 | `A6` 播 U 盘索引 1 / 2 / 99 / 0 | **全程无声**，`C9` 也从未因它变化 |

由此得到的结论（这就是"应用里没声音"的根因）：

1. **索引 1 的文件确实存在**（`AD` 能把它播出来），而 `A6 索引 1` 连发 4 次都无声
   ⇒ **不是索引号 / 文件的问题，是本模块的 `A6`（指定 U 盘根目录索引播放）收下命令但不播**
   （它只回一个固定字节 `05`）。
2. **播放引擎与音频链路完全正常**：`AC` / `AD` 从"停止态"也能起播，`C1 = 1F`（音量满）、
   `B6 = SPK`、每一步的帧长度/校验都对 ⇒ 硬件、接线、协议都没问题。
3. 所以 8.4~8.7 里"改用 `A6` 就有声"的说法**不成立**（那几轮听到的声音其实来自后面的
   `AC`/`AD` 步骤）；正式播指定语音请改走 **`A7` 按文件名播放**。

#### 8.9.1 前置条件（硬件 + 文件）

* U 盘：`D+` / `D-` / `5V` / `GND` 四根都接；格式 **FAT / FAT32**；音频放**根目录**。
* 喇叭接 **`SPK+` 与 `SPK-` 两端**（模块内部是 BTL 桥接功放）；任一端接 `GND` 会永远无声。
* **`A7` 要求文件名固定 4 个字符**（扩展名另算）：`T001.mp3` / `T002.mp3` … →
  命令数据就是 `"T001"` / `"T002"`
  （帧 `7E 07 A7 54 30 30 31 93 EF` = 播 `T001.mp3`，`7E 07 A7 54 30 30 32 94 EF` = 播 `T002.mp3`；
  长度 `07 = 1(自身) + 1(命令) + 4(名字) + 1(校验)`，校验 = 从长度字节起逐字节累加取低字节）。

#### 8.9.2 新增"按文件名轮播"（当前固件默认开启）

| 配置（`Inc/bsp_config.h`） | 当前值 | 说明 |
|---|---|---|
| `WT2003_PROBE_ON_BOOT` | **`0`** | 38 步自检**已关闭**（第五轮结论已拿到，不再上电跑） |
| `WT2003_NAME_CYCLE_ON_BOOT` | `1` | 上电即开始按文件名轮播 |
| `WT2003_NAME_CYCLE_MS` | `4000` | **每 4 秒播下一个文件**（要 ≥ 单个音频时长，否则下一首会切掉上一首） |
| `WT2003_NAME_CYCLE_QUERY_MS` | `800` | 播后 0.8 秒自动查一次 `C9` + `CB`，确认"模块到底播的是哪一首" |
| `WT2003_NAME_CYCLE_LIST` | `{"T001"…"T005"}` | 按 U 盘里的**真实文件名**改（`C7 = 5` 说明模块认到 5 个文件） |

上电后的日志形态（听到声音时直接对名字）：

```
NAME 1/5 "T001" play by file name (A7), rx=12
WTTX 7E 07 A7 54 30 30 31 93 EF      ← A7 播文件名 "T001"(长度 07 = 1+1+4+1, 校验 93)
WTRXRAW 7E 04 A7 00 AB EF            WTRXINFO A7 ret=0x00
WTRXINFO cur_file=1                  ← C9: 播放指针动了吗
WTRXINFO name="T001.mp3"             ← CB: 模块实际在播的名字(能对上 = A7 生效)
```

> `A7` 的回码同样可能是本固件私有的 `05`（像 `A6`/`D2`/`C7` 那样）——
> **回 `00` 还是 `05` 都不代表结果**，请以"耳朵 + `CB` 的 `name=`"为准。

判读：

* `cur_file` / `name=` 都跟着变 ⇒ `A7` 生效：把 `WT2003_NAME_CYCLE_LIST` 换成真实名字，
  业务层直接调 `wt2003_play_udisk_name("T00n")` 就能点播。
* 有声但 `name=` 是空 / 老值 ⇒ 名字没对上（不在根目录 / 不是 4 字符 / 大小写不符）。
* 完全无声且 `A7` 回 `01` / `02` ⇒ 名字不存在（`02 = EMP` 无此文件），按 8.9.1 核对文件名。

#### 8.9.3 远程命令（不重烧也能试，见第 4 节命令表）

| 命令 | 作用 | 回文 |
|---|---|---|
| `VNAME` | 列出配置里的名字表 | `OK VNAME n=5 every=4000ms` + 每行 `NAME 1 "T001"` |
| `VNAME 3` | 立刻用 `A7` 播第 3 个名字 | `OK VNAME 3 = "T003" (A7 U-disk by name, see WTRX)` |
| `VNAMEON` / `VNAMEOFF` | 开 / 关"每 4 秒播下一个"的轮播 | `OK VNAMEON 5 files, 4000 ms each` |

驱动接口：`wt2003_name_start / stop / fire / count / get / set_handler`（`drv_wt2003h.h`）。
`wt2003_name_start()` 与 `wt2003_probe_start()` **互斥**（谁后开谁生效），
避免两套时序交叉把日志搅乱。

### 8.10 收尾
`WT2003_PROBE_ON_BOOT` / `WT2003_NAME_CYCLE_ON_BOOT` 选一个为 `1`（其余 `0`）、
`WT2003_TX_TRACE` / `WT2003_RX_TRACE` 根据需要置 `0`（正式固件静默）；
`WTPROBE` / `WTSTOP` / `WTST` / `WTRAW` / `VOUT` / `VQRY` / `VCHECK` / `VPLAY` / `VPLAY6` / `VPLAY0` /
`VNAME` / `VNAMEON` / `VNAMEOFF` / `VKEY`
可留着当维护工具（不收到命令就不动作）。
